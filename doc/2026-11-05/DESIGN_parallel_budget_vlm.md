# ANALYSIS — MQT-LLaVA「随机预算」→「并行预算」：AssocVTC 并行/循环架构切换的参考价值

- 日期: 2026-11-05 ｜ 状态: 分析（未开跑）｜ 关联实验: Qwen3.5-4B + 448²/p32/960M 阶段2 编码器（B/ckpt_best.pt）
- 上游问题（用户）：*「把 arXiv:2405.19315（MQT-LLaVA，可变视觉 token）的**随机架构**改成**并行架构**；AssocVTC 9 月那次从并行换循环的实验有没有参考价值？」*
- 结论先行：**有参考价值，但要分两层看**——①「并行 vs 循环的**解码器结构**」这一层**不可直接迁移**（MQT 的预算是嵌套前缀 + 全局文本目标，不存在 AssocVTC 那种"后步学残差⇒归零"的自锁）；②「**多预算/多变体同时训练**」这一层**有 3 条硬结论可直接用**（掩码等价、encoder-once + 变体批、无掩码=预算被切），外加 1 条**判定教训**（先确认收敛再谈税）。

## 1. 旧并行解码器为什么退化（机制，不迁移）

并行版把 T 步一次性算完，但**每步只读自己那块键 + 全局静态 `query_base`**，且损失把**每步的累积结果都监督成整图**：

- step-1 的子任务 = 完整重建（它真能做到 ~19.9 dB，S25/S64 锚点）；
- step-t 的子任务 = 预测"step-1 没做出来的残差"，而残差从 step-t **可读的键**里不可预测 ⇒ L1 的最优预测 = **0**（条件中位数）⇒ 后步输出 ≈0 ⇒ 后区 register 收不到有效梯度 ⇒ 键趋同 ⇒ 残差更不可预测 ⇒ **零增量自锁**（自洽均衡，不是训练 bug）。
- 修复必须同时动"私有目标 + 私有信息/跨步流"：循环版把 `h_{t-1}` 显式塞进下一步查询（zero-init 投影），BPTT 让末步损失能推动步 1 的 register ⇒ −30.8%。

**对 MQT 的映射：不成立。** MQT 的预算是**嵌套前缀**（预算 k 的 token = 全量 token 的前 k 个），每个预算的监督目标都是**同一段文本的完整 CE**，不是"累积预测的残差"。所以：

- 不存在"后预算学残差⇒最优=0"的自锁；
- 不需要为预算之间新增循环/跨预算结构（前缀天然共享权重与前缀关系）；
- **"并行 vs 循环"在这里不是架构选择，而是训练调度选择**：模型结构仍是 MQT（一个 query transformer 出 R 个嵌套 token），变量只是"每步训哪些预算"。

## 2. 可迁移的三条硬结论（工程事实）

### 2.1 打包的合法性：掩码是充分必要条件

- 拼接/打包多个变体做**一次**前向 ⇒ 每行 query 会 softmax 到**别的变体**的键上：9/22 实测注意力预算被切 58.9%:41.1%、梯度耦合 −40%；minival 测到 K=8/16/32 变体只拿到 **14.3/28.6/57.1%** 的注意力质量。
- **加块对角（每变体只见自己那段）后，与"逐变体独立前向"逐位相等**：9/22 `max|Δ|=0`；minival `max|Δ|=1.1e-5`（浮点级）。
- ⇒ 结论：**可以打包，但必须每变体独立掩码**；且**无掩码打包在训练后会真退化**（minival C 臂：低预算崩到 0.1147，高预算偷看全部键、部署形态崩 0.205）——这类"训练形态偷看"现象在 VLM 里对应"预算 k 的视觉 token 看到了 k 之后的 token"，必须在实现层堵死（Qwen 侧用 `attention_mask`/4D mask，别只靠因果 mask）。

### 2.2 "encoder 跑一次 + 解码器变体批"是正确落地形式（不是 varlen 拼长序列）

- minival 明确否掉了"把同图多个预算变体拼成一条 varlen 序列"：重复 token、有掩码时等价于分开算（拼长零收益）、无掩码时互相抢 softmax。
- 推荐：**共享编码一次，解码侧 `B×V` 行批** + 每变体 padding mask。真实 63M 模型探针：结构改动 ~10 行（断言 `z_s.shape[1]==num_specials` → `≤`，forward 透传 `memory_key_padding_mask`），**变体批墙钟 +1.6%**（97.3s vs 96.2s/800 步）、显存 +0.7GB。
- 玩具规模：3 变体联合训练墙钟 ≈ 单预算（103s vs 95s），显存 469MB vs 249MB。

### 2.3 随机 vs 并行：同每预算更新次数下，并行（掩码打包）更好，但差距要按同总计算复核

| 臂（minival, 3000 步收敛 regime, seed0） | K=8 | K=16 | K=32 | 每预算更新次数 |
|---|---|---|---|---|
| A 单预算×3 模型 | 0.0902 | 0.0902 | 0.0911 | 3000 |
| **B 打包+掩码（并行全预算）** | **0.0532** | **0.0522** | **0.0521** | 3000 |
| C 打包无掩码 | 0.1147 | 0.0783 | 0.0471 | 3000 |
| D1x 随机抽（论文式） | 0.0935 | 0.0925 | 0.0924 | ~1000 |
| D3x 随机抽（4500 步≈同每预算更新） | 0.0625 | 0.0627 | 0.0649 | 1500 |

- **并行全预算 ≥ 随机抽**（D3x 0.0625 vs B 0.0521，且 B 更低方差）；随机抽的代价是**每步只更新一个预算**，同计算下每预算更新次数只有联合的 1/V。
- 但 **B 的优势里混着"多任务梯度平滑/优化加速"**，玩具无法把"多任务正则"与"路径更顺"分开；**同总计算下 A 训 3× 步数再比的对照没做**。⇒ 正式实验必须补：`A(K=32) 9000 步` vs `B 3000 步 ×3 变体`（同总计算）。
- 另一条**必查**（minival §6.3）：玩具 1500 步时 40–60% 的 run 掉进差盆地；**先确认收敛步数，再谈"税"**——否则会把欠训练误判成并行训练的代价。

## 3. 落到本次 VLM 微调：具体设计

### 3.1 现状（代码事实）

- 阶段2 模型：`/root/autodl-tmp/exp448/B/ckpt_best.pt`，448²/p32/960M，`dec_dim=2048`、`K=32`、`T=16`（每步 2 token）。可出 `z_s (B,2t,2048)`，t=1..16。
- Qwen3.5-4B：`Qwen3_5ForConditionalGeneration`，LM hidden **2560**，`image_token_id=248056`，原生 vision tower 输出也是 2560 ⇒ 我们的投影头输出天然可落进 Qwen 的 visual token 槽位。
- 用户方案：`z_s (32,2048) → 线性降维 640 → (32,640) = 20,480 值 → reshape (8, 4×640=2560)` ⇒ **8 个并行 visual token**，每个 2560 维。

### 3.2 「并行预算」的两种解释（需要在评审时二选一/都做）

| 解释 | 含义 | 训练实现 | 成本 |
|---|---|---|---|
| **P1 并行预算（多预算联合训练，对应 minival B 臂）** | 每步对**同一图**同时算预算 `k∈K_set`（`k=1..8` 用前 k 个 token）的文本 CE，`loss=Σ_k w_k ℓ_k` | 视觉侧算一次 8 token；LM 侧 **同一图 × |K_set| 行批**（`B×V` 行，按 `attention_mask`/`position_ids` 处理不同长度），一次 fwd/bwd | LM 计算 ≈ V× 单预算；显存 ≈ V× 激活（可 grad-ckpt / 预算子集 {1,2,4,8}） |
| **P2 并行注入（结构上的"并行"）** | 8 个 visual token **同时**注入 LM（不是 AssocVTC 那种逐 step 读出），无预算变量 | 标准 VLM 训练（一次 fwd/bwd） | 1×，最便宜；但不解决 MQT 的"可变预算"卖点 |

用户上一轮描述（reshape 到 (8,4×640) 并行输入）字面是 **P2**；而"把 MQT 的随机架构改成并行架构"对应 **P1**。**P1 与 P2 可叠加**：8 个 token 是满预算（r=8），预算集合 = 前 k 个 token（`k=1,2,4,8` 或 1..8），P2 就是 P1 在 `k=8` 上的特例。

### 3.3 推荐实现（P1，与 minival 结论对齐）

1. **视觉侧一次前向**：AssocVTC encoder（冻结）+ 阶段2 解码器取 `z_s`（32×2048）→ 投影 640 → reshape (8,2560)。注意：`z_s` 是"读出 token"（recurrent decoder 的 memory 侧），不是 decoder 输出图；取哪个 t（2/8/16/32 token）需要定，见 §5 问题 2。
2. **LM 侧变体批**：对图 i 的预算集合 `K_set={k1..kV}`，组 `V` 行：`[vis_tok[:k] ; text]`。**不要拼成一条长序列**（minival 2.2 已否证）；用 `B×V` 行 + padding + `position_ids`，或按长度分桶（`k` 只有 4~8 种，分桶后每桶内长度一致，零 padding 浪费）。
3. **loss**：`L = Σ_k w_k · CE_k`。起点 `w_k = 1/|K_set|`；**第二臂用 `w_k ∝ 1/k`**（低预算更难，与 minival §6.2 建议一致）；报**每预算单独 CE/acc**，防止某个预算被平均掉。
4. **预算集合**：先 `{1,2,4,8}`（4 预算，成本 4×），确认趋势后再上 1..8（8×）。**MQT 原论文的随机臂**作为对照（每步随机抽 1 个 k，同每预算更新次数）。
5. **LM 侧可训练性**：先只训**投影头（2048→640→2560）+ 少量 LoRA**（r=16/32, q/k/v/o + MLP），Qwen 主体冻结；否则 4B 全参 + 8 预算 × batch = 显存/算力都爆。
6. **防泄漏**（2.1 的教训）：变体行之间**不能**共享注意力；用独立的 `attention_mask`（每行只见自己的 token），不要在一条序列里靠因果 mask 兜。
7. **prompt/position**：文本位置随 k 变化 ⇒ 每行 `position_ids` 从 0 开始重排（或视觉段 + 文本段分别编号），否则不同预算的文本位置不一致，CE 不可比。

### 3.4 成本粗估（待实测，按 A800 80G 单卡）

- Qwen3.5-4B LoRA (bf16, grad-ckpt, sdpa)：单条 ~300 token 序列 fwd+bwd ≈ 0.1–0.2 s（数量级）；`B=16`、`V=4` ⇒ 64 行/step ⇒ ~6–13 s/step。IN-100 121,689 图、1 epoch ≈ 7,606 步（B=16）⇒ **13–27 h/epoch**；V=8 再 ×2。**必须**用预算子集/更小 batch/更少图（如 5k 子集先跑通）。
- 显存：LoRA + bs16×V4 行（最长 ~300 tok）估 25–45G（grad-ckpt），可在 1 卡跑；DDP 2 卡分摊。

## 4. 判定标准与消融顺序

**先跑通、再谈赢**（minival 的教训：欠训练会把机制差误判成税）：

1. **Step 0｜收敛步数标定**：只训 `k=8`（满预算）一个臂，确认 CE/acc 进入平台（IN-100 100 类，acc 应到 ~85–90%+；用现有自蒸馏数据的 nothink 版做 SFT）。**在平台之前不比任何臂。**
2. **Step 1｜同每预算更新次数**：`A 随机`（MQT 式）vs `B 并行 {1,2,4,8}` 各训到"每预算总更新次数相同"；指标 = 各预算 acc/CE + **预算增量收益**（k=1→8 的 acc 差值；Δ≈0 ⇒ 预算没用上）。
3. **Step 2｜同总计算**：`A 训 4× 步数` vs `B`；这是 minival 没做、本次必须补的对照（决定"并行是不是白送"）。
4. **Step 3｜loss 权重**：`1/k` vs 平均 vs `p_full` 保底（先验：低预算样本少，1/k 偏向小 k）。
5. **Step 4｜（可选）P2 特例**：只训 `k=8`（单预算）作为上界；若 P1 的 k=8 与 P2 差距 ≤ 噪声，说明并行约束没伤满预算。
6. **必报的诊断**（对应 AssocVTC "逐 step 曲线/step_px_scale"）：每预算 acc 曲线、**截断-满预算 gap**（k=1 vs k=8）、**视觉 token 注意力质量**（文本 query 对 8 个 visual token 的注意力分布是否被前几个吃掉）——这是"零增量自锁"在 VLM 侧的同构探针。

## 5. 与 AssocVTC 的差异 / 风险（不迁移的部分，写清楚免得被类比误导）

1. **无残差自锁**：MQT 每个预算都有完整目标，不会出现"后预算最优输出=0"。⇒ 不需要循环结构、不需要 BPTT、不需要跨预算 carry。
2. **"预算被切"不能靠架构修**：AssocVTC 的并行退化靠"循环"修；VLM 侧对应风险是"LM 只用前 1–2 个 token 就够了"（预算塌缩），这是**数据/损失/权重**问题，不是结构问题；诊断见 §4.6。
3. **打包 vs 批**：VLM 的变体是**不同长度**的序列，`B×V` 批最干净（bit-exact），拼一条序列需要 4D 块对角 mask + 位置重排，收益只有"少几次 kernel launch"——先别做。
4. **随机 ≠ 差**：MQT 论文自己就是随机采样；minival 的 D 臂在"同每预算更新次数"下略逊于 B，但**方差大且未测同总计算**。⇒ 本实验的卖点应写成「**并行全预算训练**是否在**同总计算**下优于随机采样」，而不是"并行一定更好"。
5. **预算集合离散度**：`k∈{1..8}` 的 k=1 信息量太低（1 个 2560 维 token 描述整图），可能拖累共享投影头；建议预算集合起步 `{2,4,8}`，并在 §4.6 检查 k=1 是否"白训"。

## 6. 待用户确认的问题（影响排期）

1. **P1 vs P2**：这次到底做「并行**预算**训练」（每步多预算）还是只做「8 token 并行**注入**」（单预算）？还是 P1 为主、P2 作 k=8 上界？
2. **用哪个 t 的 z_s**：阶段2 的 `z_s` 有 2/8/16/32 token 四档（t=1/4/8/16）；8 行 × (4×640) 需要 **32 token**（t=16），但也可以用 t=4 的 8 token 直接 → 8 行（每行 1 个 2560 维），需要确认"降维 640 再 4 拼 1"是不是刻意设计。
3. **训练数据/目标**：用现有 IN-100 自蒸馏 nothink/think SFT（100 类闭集分类 + 理由），还是换 caption/instruction 数据？这会决定"预算增益"指标怎么算。
4. **可训练范围**：投影头 only / +LoRA（推荐）/ 全参？
5. **GPU 排期**：GPU0 在跑 S3-zs448（~21:40），GPU1 在跑 Qwen 数据生成（~21:45）；VLM 训练排在它们收口后 → 今晚可先写代码 + 单卡小规模（1k 图、k=8）跑通。
