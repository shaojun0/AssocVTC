# REPORT — 8步循环解码复核：剔除 rFID（λ=0）+ 448 瓶颈臂，2026-11-20/21

> **一句话**：上次 18.04 dB 的塌点**是 rFID λ=1.0 造成的，不是 8 步循环解码本身**——单变量去掉 rFID 后
> zs192 达 **21.83 dB**（patchDC +3.76）、zs448 达 **23.11 dB**（+5.04），8 步全程单调、无伪影，而且 λ=0 连 rFID
> 指标本身都更好（102.5 vs 116.3）⇒ 该损失在此设置下**纯有害**。但 8 步在同值预算下仍比 T=1 低 **3.4~4.2 dB**：
> 加宽瓶颈（192→448）能把曲线抬 1 dB 却把差距**拉得更大**，短板是**循环读出在高码率端的 rate-scaling 折扣**，
> 不是瓶颈宽度（§5.4）。

**结论**：rFID λ=1.0 不仅把 PSNR 打掉 3.76 dB、把末步打成"掉点"、引入棋盘格伪影，
连**它自己的优化目标 rFID 也没变好**（116.3 vs 102.5）。即上次报告里"8 步循环解码失败"的判断需要修正为：
**8 步循环解码在 3ep + T=1 热启动下能训到 patchDC+3.8 dB，是 λ=1.0 的批次 Fréchet 辅助项把它打崩的**。
（训练日志也直接印证：同 step 950，λ=0 recon=0.2626，λ=1.0 recon=0.3994 —— rFID 在跟重建抢梯度。）

### 3.4 新的真实短板：后段步数不涨点

| 增量区间 | 新增值 | ΔPSNR |
|---|---|---|
| 192 → 384 | +192 | +0.98 |
| 384 → 576 | +192 | +0.27 |
| 576 → 960 | +384 | +0.27 |
| 960 → 1344 | +384 | +0.21 |
| 1344 → 1920 | +576 | +0.37 |
| 1920 → 2496 | +576 | **+0.01** |
| 2496 → 3072 | +576 | +0.13 |

从 192 到 3072 值（**16×** 码率）总共只 +2.24 dB；作为对照，T=1 从 256 值（20.03）到 3072 值（25.25）
同样的 12× 码率提升拿了 **+5.2 dB**。也就是说：**前 3 步利用率正常，step 6 之后基本饱和**
（step7 甚至 +0.01）——这是 8 步读出机制在 3ep 预算下的真实瓶颈，也是 B 臂要检验的点。

### 5.4 判定：瓶颈宽度**不是**主因

1. **加宽确实有效**：B 比 A 每个 epoch 高 +0.9~+1.3 dB，末步 +1.28 dB，rFID 从 102.5 → 63.7（**1.61× 更好**）。
   说明秩-192 截断（SVD 相对误差 **0.781**）确实吃掉了重建能力，**"秩-192 太窄"这一条成立**。
2. **但没有解决问题，差距反而变大**：同值预算下 A 差 T=1 3.38 dB，B 差 T=1 **4.17 dB**。
   T=1 从 3072→7168 值（2.33×）拿到 **+2.07 dB**，而 8 步只拿到 **+1.28 dB**。
3. **两条臂落在同一条 rate–distortion 轨迹上**，宽度只是沿轨迹平移：

   | 等值对照 | A | B |
   |---|---|---|
   | ~448 值 | step2 384 值 20.61 | step1 448 值 20.56 |
   | 1344 值 | step5 21.37 | step3 **21.88** |
   | ~3100 值 | step8 3072 值 21.87 | step5 3136 值 **22.39** |

   ⇒ 高码率端宽度带来约 **+0.4~0.5 dB/等值**，但整体仍远低于 T=1 曲线。
4. **饱和模式两臂一致**：A 增量 `+0.98/+0.27/+0.27/+0.21/+0.37/+0.01/+0.13`，
   B 增量 `+0.86/+0.45/+0.24/+0.27/+0.48/+0.17/+0.11`——都是 **step6 之后骤降**。

**结论：8 步循环解码的短板是「读出机制在高码率端的 rate-scaling 折扣」，不是瓶颈宽度。**
加宽瓶颈能把整条曲线抬起约 1 dB，但抬不动它的**斜率**。这与「T=1 热启动 + 3 epoch」的预算假设一致：
循环 decoder 需要长预算（主线是从零 45ep）才能学会把后几步的 token 真正用起来。

## 6. 结论

1. **上次的 18.04 dB 塌点是 rFID 造成的，不是 8 步循环解码本身**。单变量对照（只把 λ=1.0→0）：
   末步 PSNR 18.11→**21.87**（+3.76 dB）、L1_255 21.50→13.94、rFID 116.3→**102.5**（连它自己的目标都更好），
   末步掉点与棋盘格伪影同时消失。**rFID λ=1.0 应废弃**；若还要用，λ∈[0.01,0.1] + 慢 ramp + PSNR 护栏。
2. **8 步循环解码在"T=1 热启动 + 3ep"预算下是可训的**：zs192 21.83 dB（patchDC **+3.76**）、
   zs448 23.11 dB（patchDC **+5.04**），8 步全程单调、无伪影、定性图只有模糊没有花纹。
3. **瓶颈宽度不是主因**：zs192→448 让整条曲线抬高约 1 dB（末步 +1.28 dB、rFID 1.61× 更好），
   但同值预算下与 T=1 的差距反而从 3.38 dB **扩大到 4.17 dB**；两条臂的增量都呈"step6 后骤降"
   （A: +0.37→+0.01→+0.13，B: +0.48→+0.17→+0.11）。
   ⇒ 短板是**循环读出机制在高码率端的 rate-scaling 折扣**，抬得动曲线、抬不动斜率。
4. **最可能的机制假设（待验证）**：现在 8 步是**平权 L1**，但累积读出下前几步（1~3 个 token）的 L1 远大于后几步
   （L1_255 18.8 vs 13.9），梯度被前段主导 ⇒ 后段步数学不到高频细节。
   **建议的第一优先实验：逐步加权（后段加权 / 按各步初始 L1 反比加权）**，若后 3 步增量抬起来，即证实此假设。
5. **正向价值仍然成立**：8 步模型一个权重给出 8 个嵌套码率点，低码率端与 T=1 相当
   （A step1：192 值 19.63 dB；T=1 zs16：256 值 20.03 dB），适合渐进传输/单模型多码率。
6. **与 ALIT 仍差 5.8×（T=1 口径）~12.4×（8 步口径）**，主因是口径与预算：我们 448²（同值数下每 value 覆盖
   196 px，ALIT 只 64 px）、无 GAN stage、3 epoch vs 400 epoch。要做真可比，应**对齐到 256²** 跑一次。
7. 后续优先级：① 逐步加权（成本最低，1 次 3ep 即可验证）；② 循环 decoder 从零长预算 / 先 zs_dim=0 训循环再压瓶颈；
   ③ 对齐 256² 做 ALIT 公平对照；④ 若要 rFID，只作小权重辅助。

## 7. 复现

