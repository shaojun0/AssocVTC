## 3. 逐块 PCA 基线（同信息量）

### 3.1 口径

- **基的拟合**：ImageNet-100 **训练集**前 400 张图（等距取样）的 78,400 个 16×16×3 patch（768 维，0–255 空间）上拟合 **共享** PCA 基；`mean` (768) + `basis` (768×256)，**非逐图 oracle**、非逐图拟合。
- **实现**：协方差 `Σ` 的 **float64 累加** + `torch.linalg.eigh(768×768)` 精确特征分解取前 q 个特征向量（不用随机化 `pca_lowrank`，避免基随 seed/设备漂移；特征向量符号不影响重建）；`torch.manual_seed(0)` 仍在拟合前固定。前 5 主成分解释方差 0.7014 / 0.0649 / 0.0414 / 0.0371 / 0.0143；前 256 累计 0.9964。
- **重建**：每图 196 个 patch 各取前 r 个主成分系数，再乘回共享基 → 存 PNG（与模型同口径）。
- **信息量**：每图 **196×r** 个连续值 + 768×256 共享基（基算"模型参数"，不计入每图预算，与 `baseline_svd_stepwise.py` 的约定一致）。

## 4. 同信息量对照（论文表 `tab:alit` 的依据）

按"每图连续值个数"对齐：本文 1 个 token = 1248 维 ⇒ 8/16/32 个 token 当量 = 9,984 / 19,968 / 39,936 个值；PCA rank r 的每图值数 = 196r ⇒ rank **51/102/204** = 9,996 / 19,992 / 39,984（对齐误差 <0.12%）。

| 每图 token 当量（1248 维/块） | 8 | 16 | 32 |
|---|---:|---:|---:|
| 本文（16 步读出，T=16） | 49.30（第 4 步） | 26.83（第 8 步） | 19.97（第 16 步） |
| 本文（单步读出，T=1） | / | / | 6.13 |
| PCA（逐块，同信息量） | 23.31（rank 51） | 9.02（rank 102） | 2.12（rank 204） |

**结论**：同连续值预算下 PCA 的 rFID 明显更低（像素 PSNR 也更高：rank 204 为 35.75 dB，本文 16 步为 27.94 dB）。原因不在"信息预算不够"，而在两者的压缩对象不同：
- PCA 的码保留 **196 个 patch 位置**（每位置 204 维系数），序列长度**没有减少**，且不能按步截断成更少预算；
- 本文把整图路由到 **32 个 1248 维 token**，token 数 196→32（6.12×），单一模型可按读出步数覆盖 2–32 token 的多档预算。

> 该结论与仓库既有报告一致：`doc/2026-10-23/REPORT_n2bigstep.md` §0（"同预算 SVD rank-30 28.57 dB vs 模型 24.74 dB（+3.83 dB）"）与 `doc/2026-10-24/REPORT_scale_ladder.md` §2.2（"逐块线性码在高预算端更强：t=16 PCA rank-73 L1 6.62 vs m240 7.00"）。本轮把 N=2/T=16 的 240M 档补上了 **rFID** 口径。

## 5. 一个必须写清的口径修正：token 维度不是 448

任务书 2026-10-26 的文字按旧 63M 架构估计"模型每图信息 = 32×448 = 14,336 个数 ⇒ PCA rank 73"。但 240M 档的 ckpt 实测：

```
torch.load(...)["cfg"]: enc_dim=1248, dec_dim=1440, num_specials=32
encoder(x) → z_s = (B, 32, 1248)
```

⇒ **每图信息量 = 32×1248 = 39,936 个连续值**，同信息量 PCA 应为 **rank 204**（196×204=39,984），不是 rank 73（196×73=14,308，只有本文的 35.8%）。
本报告同时给出 rank 37/73/146 等备用点（任务书要求），论文正文以 **rank 204** 作为"同信息量"对照，并在表注里写明 token 为 1248 维、PCA 每图 196r 个值的对齐方式。

## 8. 风险与边界

1. **PCA 更强不是 bug**：逐块线性码保留 196 个空间位置、每位置独立编码，像素/rFID 上本来就强于 32-token 瓶颈（仓库 10-23/10-24 两轮已记录）。论文按"压缩对象不同"如实解释，不写成"本文优于 PCA"。
2. **信息量对齐以连续值个数计**：若改用 bf16/量化比特数，两个数都会变；本文无量化、无熵编码，论文已声明"压缩率以 token 数度量，不是 bpp"。
3. **rFID 不可跨模型底座比较**：本文与 PCA 同协议同数据可比；TiTok/ALIT 带 VQGAN 量化底座、分辨率/评测集不同，故表中只标位置不填数。

## 9. 附：L1/PSNR 的「严格同值数对齐」复核（2026-10-26 追问）

**问题**：README/10-24 的逐步 L1 曲线里"低预算端模型 L1 优于 PCA"，但 rFID 表里 PCA 明显更好——两个结论是否矛盾？

**结论**：不矛盾，但"L1 优于 PCA"是**对齐口径**造成的（PCA 被给了 0.36× 的值数）。按每图连续值个数严格对齐后，**PCA 在 L1、PSNR、rFID 三项上全程领先**，且 L1/PSNR 的差距随预算增大而**扩大**。

### 9.1 两套对齐

- 旧曲线（10-24 `scale_stepwise_l1.png` / `pca_stepwise_curve.csv`）：`r = round(896·t/196) ≈ 4.57t`，即每步 896 个值 —— 这是**旧 63M 宽度**（2 token × 448）的预算；240M 档每步是 2 × 1248 = **2,496** 个值 ⇒ PCA 只拿到 **0.36×** 预算。
- 严格对齐（本节）：`r = round(2496·t/196) ≈ 12.73t`（13/25/38/51/64/76/89/102/115/127/140/153/166/178/191/204）。

### 9.2 严格对齐结果（5,000 张 val，同 0–255 不 clamp L1 口径）

| t | 值数 | 模型 L1 | 模型 PSNR | 模型 rFID | PCA rank(值数) | PCA L1 | PCA PSNR |
|---|---|---|---|---|---|---|---|
| 1 | 2,496 | 13.50 | 22.07 | 115.30 | 13(2,548) | **12.41** | 23.21 |
| 2 | 4,992 | 11.72 | 23.19 | 89.78 | 25(4,900) | **10.06** | 25.10 |

### 9.3 旧口径为什么看起来"模型更好"

同一条 PCA 曲线按 4.57t 对齐时：t=1 PCA（rank 5，980 值）L1 16.69 vs 模型（2,496 值）13.50；t=4 11.21 vs 9.53；t=13 7.28 vs 7.17（差 −0.12）；t=14 起 PCA 反超（7.03 vs 7.10），t=16 6.62 vs 7.00。所谓"低预算端模型 L1 更好"＝用模型每步 2,496 个值去比 PCA 的 980–1,120 个值。

### 9.4 为什么 rFID 的差距比 L1/PSNR 大（指标语义）

- **L1/PSNR 是逐像素、逐图的失真**，主要被低频（亮度/布局）误差支配；模糊在 L1 上很便宜。
- **rFID 是集合级 InceptionV3 pool3 特征的分布距离**（均值+协方差），主要由**纹理/锐度统计**与全局色彩统计决定，不看逐图对应关系。
- 实测（`recon_samples/` 4 张）：梯度能量 GT 10.94 → PCA rank204 **10.79（98.6%）** / 本文 16 步 **7.93（72.5%）**（第 1 步仅 4.64=42%）。纹理能量丢 27%，L1 只罚 7.0 px，但特征协方差缩水 ⇒ FID 被放大（19.97 vs 2.12，9.4×；而 L1 仅 2.1×、MSE 6.0×）。
- 机制：39,936 个值被压进 **32 个向量**，且用像素级监督训练 ⇒ 解码器输出接近给定 token 的条件均值（模糊是 L1/PSNR 意义下的最优响应）；而 PCA 把预算摊在 **196 个空间位置 × 204 维**上，高频纹理是局部的，在逐块编码里存活、在 32-token 瓶颈里死掉。所以"信息量相同"并不等于"信息放的位置相同"。
