## 0. 结论（一句话）

**"编码一次 + 变体独立掩码一次前向/反向"的打包联合训练机制成立，而且在收敛 regime 下不是"零税"而是"负税"**：一个模型同时训 K∈{8,16,32}（3000 步，所有臂都已收敛），K=32 的测试 L1 = **0.0521**，比"单预算 K=32 模型"的 0.0911 **好 42.8%**（tax = **−42.8%**）；K=8/16 分别为 **0.0532 / 0.0522**（与自己 K=32 持平，且远好于单预算 K=8 的 0.0902），证明低预算**真的被训练到了**。而不联合训练时，K=32 模型截断到 K=8 会退化 **2.18×**。去掉掩码的对照组按 9/22 预测的方式退化：注意力质量被切成 **14.3% / 28.6% / 57.1%**，K=8 落后 B **2.16×**、K=16 落后 **1.50×**；无掩码模型的 K=8 变体实际在"偷看"全部 token（训练形态 packed 推理 0.100 vs 部署形态 0.205），**不可部署**。

> 重要口径修正 1：Lead 方案里"把同一张图的多个预算变体打包成**一条 varlen 序列**"不是最优形式 —— 同一张图的 3 个变体拼成一条序列会产生**重复 token**，有掩码时等价于分开算（§3.1 有逐位验证），无掩码时重复键互相抢 softmax 质量。真正要实现的并行形式是「**encoder 跑一次 + decoder 以 B×V 行做变体批 + memory_key_padding_mask**」，收益来自共享编码，不是把 token 拼长。
> 重要口径修正 2：1500 步时这个小任务**所有臂**（A/B/C/D 都一样）有 30–50% 的 seed 掉进 L1≈0.17–0.19 的差盆地，这一 regime 的组间均值没有解释力（30% 的"税"可以是纯 seed 彩票）。主结果因此换到 3000 步的全收敛 regime；正式实验前必须先确认收敛步数，否则会把"欠训练"误判成"对齐税"。

## 1. 科学问题与判定标准

要回答两件事：

1. **打包联合训练到底对不对** —— 一个模型同时训 K∈{8,16,32}，能否 (a) K=32 不掉点（不交"对齐税"），(b) K=8/16 也真的被训练到（不是陪跑）？
2. **无掩码会怎样** —— 9/22 的"预算/梯度耦合"警告在**训练层面**是否成立？

判定标准（写死，避免事后解释）：
- **机制成立**：B≈A（|tax|≤5%）且 C 明显差于 B；
- **反例**：B 明显差于 A → 记录并分析是梯度冲突还是变体耦合；
- D（随机抽）波动大但均值接近 A → 随机抽只是方差问题、不是能力问题。

> 执行补充：原设计是"每臂 1500 步"，但 1500 步时这个小任务出现**全臂共有**的双峰收敛（见 §3.2），组间均值被 seed 彩票淹没。因此追加了 **3000 步全收敛 regime**（seed 0）作为主判据（§3.3），1500 步的 4-seed 结果保留为"欠训练 regime"的证据。

## 2. 玩具实验设计（Track 1，自包含纯 PyTorch）

脚本：`track1/minival.py`（约 500 行，单文件，无外部依赖）、`track1/rerun_seeds.py`、`track1/analyze.py`

### 2.1 数据
- 合成图像 32×32×3：随机深色背景 + **2–4 个彩色几何图形**（圆 / 轴对齐方 / 三角），随机颜色、位置、大小，加 σ=0.02 噪声并 clip 到 [0,1]。
- 固定 seed：2000 train / 200 test（seed 1234 / 5678），所有臂共用。

### 2.2 模型（0.98M 参数，encoder/decoder 权重全共享，只变 K）
```
32×32×3
 └─ Conv3→64(k4s2) → Conv64→128(k4s2) → Conv128→128(k3s1)   # 8×8×128 = 64 特征
 └─ N=32 个可学习 query 对 64 特征做 2 层 cross-attn（MQT 式 token 银行）→ z (B,32,128)
 └─ 预算 K：取前 K 个 token  z[:, :K]                          # K∈{8,16,32}，嵌套前缀
 └─ decoder：64 个像素 query（8×8 grid）对 z[:, :K] 做 2 层 cross-attn
 └─ reshape 8×8 → ConvT(128→64) → ConvT(64→32) → Conv(32→3) → sigmoid → 32×32×3
```
- 损失：像素 L1（[0,1] 空间，直接预测）。
- 预算只改变**键序列长度**，不改变 decoder 查询数（16 与 32 的 decoder 容量相同，隔离"信息瓶颈"这一个自变量；这是对 task 描述"用 K 个可学习 query"的有意偏离，已在此诚实标注）。

### 2.3 四个臂（每臂每模型固定 1500 步，batch 64，AdamW lr 1e-3 cosine→5e-2·lr，WD 1e-4，warmup 50）
| 臂 | 说明 |
|---|---|
| **A 单预算** | 3 个**独立**模型，分别只在 K=8 / 16 / 32 训练（参考基线） |
| **B 打包+掩码联合** | **1 个**模型；每步 `z = encode(img)` 只算一次，把 3 个变体的键 `[z[:8], z[:16], z[:32]]`（56 键）与 3×64=192 个像素 query 拼成一次前向，用**块对角 additive mask** 隔离变体；loss = 3 个变体 L1 的均值；一次 backward |
| **C 打包无掩码** | 同 B，但**不做 mask**（全 56 键互相可见） —— 9/22 警告的对照组 |
| **D 随机抽（MQT 式）** | 1 个模型；每步随机抽 m∈{8,16,32} 只训一个预算。D1x=1500 步；**D3x=4500 步（与 A/B/C 的"变体梯度次数"对齐：1500 步×3 变体 = 4500）** |

`A/B/C` 的 seed=0,1；补充跑到 seed=2,3（A、B），以量化单预算的 seed 不稳定性。D 只跑 2 seed（目的就是看方差）。

## 3. 结果

> 约定：L1 为 [0,1] 像素空间平均绝对误差，**越低越好**；所有臂同一数据、同一模型结构、同一 batch=64。
> "对齐税"本报告定义两次：`tax = (B 的 K=32 L1 − A 的 K=32 L1)/A 的 K=32 L1`，|tax|≤5% 视为"不交税"（负值 = 联合训练更好）。

### 3.1 机制层：掩码打包 ≡ 多次独立前向；无掩码则预算被切

在**同一组权重、同一输入**下，把 3 个预算变体打包成"56 键 + 192 像素 query + 块对角掩码"，与"3 次独立单预算前向"逐元素比较（初始化模型，8 张图）：

| 对比 | max abs diff | 结论 |
|---|---|---|
| packed + 块对角掩码 vs 3 次独立前向 | **1.1e-5** | 浮点级相等 ⇒ 打包不改变数学 |
| packed 无掩码 vs 3 次独立前向 | **3.5e-4** | 不等价（输出初始≈常数，绝对差小但非零） |

无掩码时每个变体的 query 落在**自己键块**（8/16/32 个键）上的注意力质量：

| 变体 | 自己的键数 | 落在自己键块上的注意力质量 |
|---|---|---|
| K=8 | 8 / 56 | **14.3%** |
| K=16 | 16 / 56 | **28.6%** |
| K=32 | 32 / 56 | **57.1%** |

K=32 变体的 57.1% 与 9/22 文档里两序列拼接的"58.9% : 41.1%"几乎同一个数 —— 无掩码打包把注意力预算按块大小切分，小预算变体被切得最狠（14.3%）。这是**训练前**就能预测的机制；§3.4 是它的训练后果。

### 3.2 1500 步 regime：所有臂共有的双峰收敛（先排除"伪税"）

1500 步 / 4 seeds 的测试 L1（mean ± std）：

| arm | seeds | K=8 | K=16 | K=32 |
|---|---|---|---|---|
| A 单预算（每预算独立模型） | 4 | 0.1258±0.0371 | 0.1211±0.0514 | 0.1515±0.0376 |
| B 打包+掩码 | 4 | 0.1291±0.0402 | 0.1287±0.0404 | 0.1288±0.0406 |
| C 打包无掩码 | 2 | 0.1963±0.0093 | 0.1449±0.0007 | 0.0966±0.0008 |
| D1x 随机抽（1500 步） | 2 | 0.1364±0.0526 | 0.1352±0.0537 | 0.1350±0.0539 |
| D3x 随机抽（4500 步，每预算≈1500 次更新） | 2 | 0.0649±0.0183 | 0.0627±0.0200 | 0.0625±0.0202 |

若直接按均值算，B 的 K=32 = 0.1288 vs A 的 0.1515 → tax = **−15.0%**。**这个数没有解释力**：逐 seed 看，A 的 K=32 只有 **1/4** 收敛（0.0955），其余三个卡在 0.163–0.174；A 的 K=8 只有 2/4 收敛；B 也只有 2/4 收敛（0.0916 / 0.0975，另两个 0.152–0.174）。所有臂共享同一个失败模式：**掉进 L1≈0.17–0.19 的差盆地**（训练 loss 曲线在 ~0.19 平台停留上千步），与"是否打包"无关。

**结论**：1500 步对这个小任务是欠训练，收敛与否是 seed 彩票，占掉了全部组间差异 ⇒ 判定"对齐税"必须换到**都收敛**的 regime。补充：把 A 的 K=32 单模型训到 **3000 步**，L1 从 0.174 → **0.0911**（进入收敛区）⇒ 双峰是训练步数不足，不是结构问题。

### 3.3 收敛 regime（3000 步，seed 0）：主结果 —— 不是"不交税"，是"联合训练更好"

| arm | 每预算 loss 更新次数 | K=8 | K=16 | K=32 | 墙钟 | 峰值显存 |
|---|---|---|---|---|---|---|
| A 单预算 ×3 模型（各 3000 步） | 3000 | 0.0902 | 0.0902 | 0.0911 | 3×~95s | 3×~249MB |
| **B 打包+掩码（3000 步 × 3 变体）** | 3000 | **0.0532** | **0.0522** | **0.0521** | 103s | 469MB |
| C 打包无掩码 | 3000 | 0.1147 | 0.0783 | 0.0471 | 106s | 469MB |
| D1x 随机抽（3000 步） | ~1000 | 0.0935 | 0.0925 | 0.0924 | ~100s | 244MB |

- **对齐税 = (0.0521 − 0.0911)/0.0911 = −42.8%**（负 = B 比单预算好 43%，不是交税而是"红利"）。每预算的 loss 更新次数两边都是 3000，A 还额外做了 3 份 encoder 前后向（算力上 A 更占便宜），所以 B 的优势不是算力不对等。
- **K=8/16 真的被训练到了**：B 的 K=8（0.0532）≈ B 自己的 K=32（0.0521），且远好于"只训 K=8"的单预算模型（0.0902）。
- **不联合训练就没有低预算能力**：A(K=32)@3000 截断到 K=8 = **0.1985**（K=8/K=32 = **2.18×**），截断到 K=16 = 0.1558（1.71×）；而 B 的 K=8 = 0.0532。这是"必须联合训练"的直接证据。
- 为什么 B 更好（诚实解释，**不要把 −42.8% 直接读成"打包能涨 43 个点"**）：B 每步做的是"3 个变体 loss 的**平均**"的反向 ⇒ 共享 trunk 每步拿到 3 个任务梯度的平均方向（更平滑），同时每个变体各自仍有 3000 次自己的 loss 更新。因此 B 的优势至少部分来自**多任务梯度平滑 / 优化加速**（旁证：1500 步 regime 里 B 也比 A 更早离开 0.19 平台；A、D1x 在 3000 步都停在 ~0.090–0.092 的"第二平台"，而 B 直接到 0.052）。玩具无法把"多任务正则"与"优化路径更顺"分开；而且 A 虽然单模型只训 3000 步，但 3 个模型的总计算（3×encoder）反而比 B 多 ⇒ **B 的优势不是算力不对等**。
- **要钉死的公平对照**：同"总计算"下，A 应该训到 3× 步数（≈9000 步/模型）再比；本时间盒内没跑（会占 ~15 min GPU）。所以本报告只断言：**同 step / 同每预算更新次数下，B 不交税且明显更好；同总计算下的净收益需要 A800 正实验补测**（见 §6/§7）。
- D1x 每预算只有 ~1000 次更新却达到 0.0924（≈A 的 3000 次更新），再次说明"共享 trunk 的多预算训练"本身有收益；但 D 方差大（见 §3.5），且每步只训一个预算，同总计算下每预算更新次数只有联合的 1/3。

### 3.4 C（无掩码）的退化：预算依赖 —— 低预算崩、高预算小胜

3000 步 regime（同一 seed、同一步数）：

| 预算 | B（有掩码） | C（无掩码） | C vs B |
|---|---|---|---|
| K=8 | 0.0532 | 0.1147 | **+115.6%（崩）** |
| K=16 | 0.0522 | 0.0783 | **+50.0%** |
| K=32 | 0.0521 | 0.0471 | **−9.6%（反而略好）** |

1500 步 regime 同方向（C vs B：K=8 +52.1%、K=16 +12.6%、K=32 −25.0%）。

解释与 9/22 命题 C/D 完全一致：无掩码下 softmax 质量按 14.3% / 28.6% / 57.1% 分给三个变体 ⇒ **小预算变体的梯度/表达被饿死**；而 K=32 变体不仅拿到 57%，还能"白看"其他变体的重复键，所以在最高预算上小胜。但**无掩码不可部署**：推理时一个 K=8 的样本只能拿到 8 个键，而模型训练时看到的是 56 个键（train/test 不一致），低预算在部署形态下会崩（1500 步 regime 下 C 在"只给 K 个键"的推理形态：K=8 0.1963 / K=16 0.1449 / K=32 0.0966）。

> 判定标准复核：原判定要求"C 明显差于 B"。实测 C **不是全面更差**，而是**按预算此消彼长**（低预算 2.16× 差，高预算 −9.6%）；这比"全面变差"更精确，也更符合 9/22 的"预算被切"命题。作为多预算方案，C 不可用（低预算崩 + 部署形态不一致）。

**决定性诊断（重训 C@1500，seed0）**：同一个无掩码模型，两种推理形态：

| 推理形态 | K=8 | K=16 | K=32 |
|---|---|---|---|
| 只给 K 个键（**部署形态**） | 0.2052 | 0.1737 | 0.1057 |
| 保留 56 个重复键（**训练形态**） | **0.1001** | **0.1001** | 0.1001 |

⇒ 无掩码训练出来的"K=8 变体"在训练形态下能拿到 0.1001（几乎和它的 K=32 一样好）—— 因为它**通过重复键读到了属于自己的 8 个 token 之外的全部 32 个 token**，预算约束形同虚设。一旦部署时真的只给 8 个 token，L1 立刻从 0.100 崩到 0.205（2.05×）。这是「无掩码 = 预算失去约束」的直接证据。

### 3.5 D（随机抽 / MQT 式）的方差

| 设置 | K=8 | K=16 | K=32 | 说明 |
|---|---|---|---|---|
| D1x，1500 步，seed0 | 0.1736 | 0.1732 | 0.1732 | 卡在差盆地 |
| D1x，1500 步，seed1 | 0.0993 | 0.0972 | 0.0969 | 收敛 |
| D1x，3000 步，seed0 | 0.0935 | 0.0925 | 0.0924 | 收敛 |
| D3x，4500 步，2 seeds | 0.0649±0.0183 | 0.0627±0.0200 | 0.0625±0.0202 | 每预算≈1500 次更新 |

- 1500 步 regime 下 D 的 2 个 seed 相差 **75%**（0.1736 vs 0.0993）——方差远大于 B/C，符合"随机抽只是方差问题"的预期；3000 步后收敛到 0.0924（与 A 相当）。
- 同总 backward 次数对比：D3x（4500 步、每预算 1500 次更新、总 backward 4500 次）在 K=32 达 0.0625，**优于** A 三个单预算模型各 1500 步（0.0955–0.1742）；但**劣于** B@3000（0.0521，且 B 每预算 3000 次更新）。
- 实务结论：D 实现成本最低（一行随机采样），可作为退路/对照；但同计算下不如"全预算联合"，且方差大。

### 3.6 推理侧验证：一个模型覆盖全部预算；不联合训练则低预算不可用

**B 模型（1500 步 regime，seed 0）三预算推理**：K=8 → **0.0977**、K=16 → **0.0976**、K=32 → **0.0975**（一个模型、三个都合理，且几乎与预算无关）；3000 步 regime 更好：0.0532 / 0.0522 / 0.0521。

**A 的 K=32 模型截断**（= 不联合训练的部署形态）：

| 模型 | K=8 | K=16 | K=32 |
|---|---|---|---|
| A(K=32)@1500（收敛 seed1） | 0.2863 | 0.1636 | 0.0955 |
| A(K=32)@3000（seed0） | 0.1985 | 0.1558 | 0.0911 |

⇒ 截断到 K=8 退化 **2.2–3.0×**，到 K=16 退化 **1.7×**。"先训大预算、推理时截断"不可行，必须联合训练。

**串行升级模拟**（B@1500 seed0，"oracle 置信度"= 真实 L1，仅用于量化上界）：always-K8 = 0.0977、always-K16 = 0.0976、always-K32 = 0.0975。

| 升级比例 | 平均 L1 | 平均预算 | 困难四分位覆盖率 | 升级样本中真的变好的比例 |
|---|---|---|---|---|
| 0%（永远 K=8） | 0.0977 | 8.0 | 0 | — |
| 10% | 0.0976 | 9.6 | 0.40 | 0.80 |
| 30% | 0.0975 | 12.8 | 1.00 | 0.73 |
| 100%（永远 K=32） | 0.0975 | 24.0 | 1.00 | 0.54 |

⇒ **在预算几乎等价的模型上，自适应升级最多只能换来 0.2% 的 L1 改善，却要把平均预算从 8 拉到 24**；有精度意义的策略就是"永远用 K=8"（＝用最小预算），预算变成了**纯算力旋钮**。这与项目 10/16–17「自适应 K 被否证」一致：多预算联合训练之后，K 的选择不带来精度信息。

## 5. Track 2-lite：真实 AssocVTC 模型上的探针（112×112 / patch16 / N=49）

### 5.1 可行性与卡点
- `train_linattn.py` 的 `requirements.txt` 依赖 **transformers / safetensors / accelerate / bitsandbytes / datasets** 等，weste 实例**没有**这些包，任务规定"不要硬装" ⇒ **没有跑原训练脚本**。
- 但 `model_v2_linattn.py`（63M 真实模型）**只依赖 torch**，所以直接 import 它做探针是可行的。配置：`LinAttnConfig(img_size=112, patch=16, num_specials=32)` → N=49 patches，**62.85M 参数**（encoder 31.83M + decoder 31.02M），bs=8，lr=2e-4（repo 默认）、wd=0.05、grad_clip=1.0、bf16 autocast、**300 步 + 800 步两档探针**。
- 三个臂（主档 300 步；另跑 800 步档，结论一致）：`single_K32`、`single_K8`、`joint`（**encoder 一次 + decoder 3 变体 padded memory 批 + `memory_key_padding_mask`**，loss=3 变体 L1 均值）。脚本：`track2/probe_real_model.py` + `track2/code/model_v2_linattn.py`（只读副本，未改仓库）。

### 5.2 工程结论（比数值更重要）
1. **真实 decoder 本来就是"预算无关"的**：除了 `StandardAttentionDecoder._prep()` 里一行 `assert z_s.shape[1] == self.num_specials`，memory 长度可以任意；把该属性临时改掉后，K=8/16/32 推理全部跑通、输出形状不变（`(B,49,768)` → 整图）。⇒ 正式实现只需把断言改成 `≤ num_specials`，并在 `StandardAttentionDecoder.forward` 加一个可选 `memory_key_padding_mask` 透传。**这是 Lead 方案在真实代码里唯一的结构性改动，约 10 行。**
2. **变体批几乎不增加墙钟**：300 步 `single_K32` = 38.6s，`joint`（3 变体）= **37.4s（−3%）** —— 因为 encoder 占主导、decoder 变体批在 GPU 上几乎免费。显存 1685MB → 2378MB（+0.69GB，bs 8 / 112² / 无 grad_ckpt）。这直接复现玩具的"打包≈免费"结论。
3. **吞吐（可用于 A800 规划）**：63M 模型、112²、N=49、bs=8 单卡 4080S：**~0.124 s/step（≈8 it/s）**，峰值显存 1.7–2.4GB。按 token×4（224²）、batch×4 粗估 224²/bs32 在 4080S 上 ≈2s/step；2×A800 + DDP 约 **0.3–0.5 s/step**（数量级估计，本机未验证 224²，请以 A800 实测为准）。
4. **300 步和 800 步都严重欠训练**：三个臂的像素 L1 都在 **0.189–0.193** 附近（常数输出基线 ≈0.19），300→800 步只降 0.0005–0.005；800 步时 joint vs single 的 tax = **−0.16%**、K=32 模型截断比 = 1.000、joint vs single@K8 = +1.4% —— **这些数字全是噪声级，没有解释力**。真实模型（63M，从零训练，repo 默认 lr=2e-4）在这个步数下还停在"预测灰色常数"的平台；仓库口径是 30 epochs（bs 128、~15k 步），**本时间盒内不可能训到收敛**。
   ⇒ Track 2 的实际产出是"**实现可行 + 结构改动 ~10 行 + 变体批几乎不加墙钟 + 长度无关**"，**不是** joint-vs-single 的数值结论。这也从真实模型侧再次证明：**先确认收敛步数、再谈对齐税**（否则会把欠训练的平台差当成机制差）。
5. **没有做**：真实 `train_linattn.py` 的 joint-vs-single 完整对照（受限于依赖缺失 + 时间盒），以及 224² 实测显存/吞吐。这两项建议放到 A800 上按 §6 的 checklist 做。
6. **探针数字（存档）**：300 步 / 800 步，像素 L1（`l1_pixel01`）：single_K32 = 0.1930 / 0.1921，single_K8 = 0.1928 / 0.1891，joint = 0.1935 / 0.1917；墙钟 300 步 38.6 / 36.7 / 37.4s，800 步 95.8 / 96.2 / 97.3s；峰值显存 1685–2378MB（joint 最高）。数字见 `track2/logs/results_track2*.json`。

## 6. 对 2×A800 正式实验的建议

基于玩具机制结论 + Track 2-lite 的真实代码探针（§5）：

1. **实现形式不要用"varlen 拼 token 序列"**，用「**编码一次 + 解码器变体批 + 每变体 key-padding mask**」：
   - AssocVTC 的 z_s 由同一张图编码得到，K=8/16/32 变体只是 `z_s[:, :K]`，三个变体拼成一条序列会产生**重复 token**（[z0..z7, z0..z15, z0..z31]），无掩码时重复键会互相抢 softmax 质量（玩具里 K=32 变体自己只拿到 57.1%）；有掩码时又等价于"分开算"，拼长没有收益。
   - 真正的并行收益来自：**encoder 前向/反向只算一次**（省 3×编码成本），decoder 以 `B×V` 行一次前向（`memory_key_padding_mask` 隔离变体）。玩具里 B 的 encoder 每步只跑 1 次、decoder 3 变体打包，实测仅比单预算多 ~0% 步时（53.8s vs 52.7s / 1500 步），显存 469MB vs 249MB（+0.2GB，玩具规模）；
   - 真实代码的改动量很小：`StandardAttentionDecoder.forward` 加一个可选 `memory_key_padding_mask` 参数并透传给 `nn.TransformerDecoder(...)`；`decode()` 里把 memory 变成 `[z_cls; z_s]` 的 padded 批；loss 对 3 个变体取均值。**唯一硬约束**是 `_prep()` 里 `z_s.shape[1]==num_specials` 的断言（玩具里用属性替换绕过，正式实现应改成 "≤ num_specials"）。
2. **先做 loss 权重消融**：玩具里 3 变体平权平均就够了（B 在 K=32 甚至优于单预算）。真实任务上低预算通常更难/更差，建议 `loss = Σ w_K · L1_K`，w_K 反比于该预算的收敛难度或设为 `w_K ∝ 1/K`（低预算权重大），并把它作为正式实验的第一个超参臂。
3. **训练步数要足够**：本玩具 1500 步时所有臂都有约 40–60% 的 run 掉进 L1≈0.19 的差盆地（多臂共有，不是打包特有），3000 步后全部收敛。正式实验请在正式配置上先跑"单预算 K=64"确认收敛步数，再上联合训练；否则会把"训练不足"误判成"对齐税"。
4. **对齐税用「同一步数、同一 batch」对照**：`A(K=64) 单模型` vs `B(联合) 的 K=64 变体`，比较像素 L1（或 PSNR）；同时报告 B 的 K=8/16 相对"K=64 模型截断"的增益 —— 后者是"必须联合训练"的直接证据（玩具里截断到 K=8 差 ~2×）。
5. **算力 ROI（关键卖点）**：一次 joint run（3 个预算）的墙钟 ≈ 同 step 数的单预算 run（玩具 +2~4%；真实探针 bs=8 时 +1.6%，但该 batch 下 GPU 未吃满、不能外推到 bs 128 计算密集情形）；按真实模型 encoder 31.8M / decoder 31.0M 的占比估，bs 大时 joint 每步 ≈ **1.5–2×** 单预算，仍远低于"3 个预算各跑 1 个 run"的 **3×**。即：**花 1.5–2 份算力拿到 3 个预算的模型**，并且低预算能力是"真训出来的"（不是截断出来的）。显存按变体批估约 +2/3 的 decoder 激活；2×A800 建议 img 224 / patch 16 / K=64、batch 64/GPU（grad_ckpt 兜底）。
   - 粗估（用实测 112²/bs8 ≈0.12s/step 外推，仅数量级）：224²/bs64 在 4080S 上 ≈4s/step，2×A800 DDP 约 **1–1.5s/step**；repo 默认 30 epochs（≈15k 步）单预算约 **4–6 h**，joint 约 **6–9 h**（拿 3 个预算）。实际以 A800 实测为准。
6. **工程护栏**：沿用仓库已有的 `grad_clip=1.0` + `skip_grad` 梯度爆炸跳步护栏（10/19 的教训），并给每个变体的 loss 单独记日志（便于发现某个预算被"平均掉"）。

## 7. 诚实边界（玩具 ≠ 真实任务）

1. **任务太容易，预算区间被压扁**：合成图像只有 2–4 个纯色几何图形，K=8（8×128 维）已接近信息饱和，B 的 K=8 只比 K=32 差 0.6%。因此本实验**无法**测出真实 448 主线里"K=8 → 64 单调上升"的预算曲线，也无法测出"低预算对齐税"的真实量级；能测的是**机制**（掩码等价性、预算耦合方向、联合训练可行性）。
2. **模型太小（0.98M vs 真实 63M）**、只训 1500–3000 步、无预训练、无 DINOv2/线性注意力复杂性；真实模型的优化地貌与玩具不同（10/19 已见 K>64 优化受限）。
3. **实测的是两相机制（32×32 → 8×8 特征 → 32 token → 像素）**，与真实 448 主线的 "patch token + cls + specials 同序列双向注意力" 不完全同构；但"z_s 是同一张图的压缩表示、预算 = 前缀 token 数"这一核心同构成立。
4. **无掩码对照的退化同时混入了"训练/推理不一致"**：C 臂训练时看到 56 个重复键，推理时只能给 K 个键。真实实现若坚持无掩码，要么推理时也拼重复键（等于作弊、预算失去意义），要么承受不一致。这只会让"无掩码不可用"的结论更强，但也意味着**不能把 C 的全部退化都归因于注意力预算被切**。
5. **对齐税统计受 seed 双峰影响**：1500 步 regime 下 A/B 都有约一半的失败 run，均值 ± 标准差不能直接当"税"；本报告用"收敛 regime（3000 步）+ 逐 seed 收敛判定"来给税，样本量仍小（1–4 seed），只能作为方向性证据。
6. **串行升级是 oracle 模拟**：升级阈值用的是真实 L1（推理时不可得），只用来量化"如果有一个完美置信度信号，多预算模型能省多少预算"，**不是**可部署策略。
