## 1. 方法与口径（与主线 eval 逐项一致）

| 项 | 本基线 | 说明 |
|---|---|---|
| 数据 | `/root/autodl-tmp/datasets/imagenet100`；`data_linattn.build_datasets(data_dir, img_size)` | val = 每类等距抽 50 = **5,000 张**（与主线 eval 同划分）；基**只用 train** 拟合 |
| patch 向量 | `model_v2_linattn.image_to_patches(x, patch)`（通道优先、row-major）；224²/p16 → 768 维，448²/p32 → **3072 维** | **N=196 不变**（本扩展设计 patch 面积 ×4、N 保持） |
| 拟合空间 | **0–255 patch 空间**（`x·STD_255 + MEAN_255`，不 clamp） | 与 `eval_rfid_pca.py` 一致 |
| 基 | 协方差精确 `eigh`（float64 累加 `s1/s2`，取前 q 个特征向量）；**train 共享基、非逐图 oracle**；基存储算「模型参数」，**不计入每图值数** | 224 重拟合用论文同款 400 张（等距抽、seed=0）；448 用**全量 train 121,689 张** |
| 每图值数 | PCA = **N×r = 196r**（r=1…40）；模型 S3 臂 = **2t×224 = 448t**（t=1…16 ⇒ 448…7168） | 按最接近值数取 rank，另给「精确值数插值」列（= 论文表 2 PCA 行做法） |
| PSNR | `patches_to_image(..., IMAGENET_MEAN, IMAGENET_STD).clamp(0,1)` → `metrics_linattn.psnr` **逐图再平均** | 与主报告 `eval_linattn` 同口径 |
| SSIM | `metrics_linattn.ssim`（11×11 高斯窗 σ=1.5、裁边界、通道均值），输入同上 [0,1] | 与 `eval_linattn` 同函数 |
| L1_255 | 0–255 空间、**不 clamp**、逐图平均 | = `eval_stepwise_linattn.py` 的 `L1_255` 口径（不是 `/255`） |
| 模型列 | 读 `/root/autodl-tmp/exp448/eval/stage3_stepwise.json` 的 `PSNR`/`L1_255`（16 档） | 当前**不存在（TODO）**；产出后重跑脚本即自动填（§3.3） |

**为什么「非 oracle」**：PCA 基只在 train 上拟合，val 图逐个投影重建，**没有**在评测图上拟合基（后者是 transductive oracle 上界，仓库 2026-10-30 的 zs-PCA 报告用过、不可与论文比）。因此本表与论文表 2 的 PCA 行可直接比。

**值数对齐细节**：模型 S3（`--zs_dim 224`）第 t 步累计读出 2t 个 token、每 token 224 维 ⇒ 448t 个连续值。448 的 N 仍是 196，所以 PCA 侧 `r_exact = 448t/196 = 2.286, 4.571, …, 36.571` 不是整数：表里同时给「最近 rank 实测」与「相邻 rank 线性插值（精确同值数）」，后者才是论文表 2 的正式口径（+0.005 dB 内可复现）。

## 4. 448 vs 224：同值数下逐块 PCA 的表现（新发现）

两者都是「train 共享基、非 oracle」的 per-patch PCA，N 都是 196，同一套 val 5000 张，**只有图像分辨率/patch 面积不同（224²/p16 vs 448²/p32）**：

| 896 | 20.409 | 20.013 | −0.396 |
| 1344 | 21.449 | 20.972 | −0.477 |
| 1792 | 22.292 | 21.736 | −0.556 |
| 2240 | 22.878 | 22.261 | −0.617 |
| 2688 | 23.325 | 22.661 | −0.664 |
| 3136 | 23.725 | 23.021 | −0.703 |
| 3584 | 24.156 | 23.389 | −0.767 |
| 4032 | 24.514 | 23.699 | −0.816 |
| 4480 | 24.825 | 23.966 | −0.859 |
| 4928 | 25.122 | 24.232 | −0.890 |
| 5376 | 25.379 | 24.437 | −0.942 |
| 5824 | 25.614 | 24.646 | −0.968 |
| 6272 | 25.857 | 24.851 | −1.006 |

解读：
- **同样的每图连续值数，重构 4× 像素必然更难**：448 的 r 与 224 相同（196r 个值），但每 patch 是 3072 维而非 768 维、每图 4× 像素 ⇒ 差值随预算扩大（低预算端 PCA 只抓 DC/低频，分辨率差异小；高预算端高频细节的"每值收益"在 448 更低）。

- **对本扩展实验的含义（S3 eval 已回填，结论）**：448 的模型 S3 臂面对同样的分辨率劣势，但**相对同分辨率 PCA 的优势几乎原样保留**：448-S3 比 448-PCA 在 448 值高 **+2.30 dB**、在 7168 值低 **−0.32 dB**；224 论文同口径是 +2.63 / −0.17 dB。也就是说，分辨率从 224→448（像素 ×4、参数 ×2）后，模型相对 PCA 的「紧预算优势」只缩了 0.33 dB、满预算端劣势只扩大 0.15 dB。**分辨率放大没有改变「模型 vs PCA」的基本形状**，交叉点仍在满预算附近（448 侧 t=14/6272 值过零）。

## 7. 局限

1. **PCA 是非 oracle 上界之外的下界型强基线**：基只在 train 拟合、val 逐图投影，**不是** transductive/oracle，也不是逐图最优秩选择（每图最优秩是 oracle 上界，仓库 2026-10-23 的 SVD 基线用过后被指出不可与模型直接比）。本基线口径与论文表 2 一致。
2. **值数相同 ≠ 结构相同**：PCA 保留 N=196 个空间位置的码（每位置 r 个系数、位置不降），模型把整图路由进 32 个 token（6.12× token 压缩、可截断）。「同值数」是论文既定口径（比的是「存储连续值个数」），不是「同等结构」。这一差异会让 PCA 在像素指标上天然偏强（尤其高预算端），解读时必须带上。
3. **指标只覆盖像素域**：PSNR/SSIM/L1_255 都是逐图失真；rFID（集合级感知距离）本轮未测（240M 轮的经验：PCA 在 rFID 上领先更多，因为纹理/锐度统计）。若论文 448 扩展要 rFID 列，需另跑 FID（约 3 min/档，GPU）。
4. **单种子 + 单个基拟合**：基的随机性只来自 train 随机裁剪（seed 0），已由 5k/20k/全量敏感性证明曲线稳定；但 seed 间波动未单独扫（预计 ≪0.01 dB，因拟合集 ≥5k）。
5. **模型列未填**：主线 S3 eval 未产出（A 相训练中，预计明天 01:00 后 A 相 eval、B 相约 15:00 后、S3 更晚），所以 §3.3 模型列/Δ 全是 TODO。填法见 §3.3 引用块。
6. **基存储不计入每图值数**：与论文/仓库口径一致（基算模型参数：3072×40 float32 ≈ 0.49 MB，相对 957.9M 参数模型可忽略；对 PCA 是「共享码本」性质的参数）。
7. **分辨率带来的整体下移**：§4 的 −0.27…−1.06 dB 是分辨率效应，不是 PCA 实现差异；448 表里所有方法（模型/PCA/ALIT）都会受同一效应影响，跨分辨率数字不可直接比。

