## 1. 背景与判据

### 1.1 实验目的（照录 PLAN §0）

把 ALIT 的三条可移植机制（**逐轮新增记忆 / 动态停机 / 逐迭代损失权重**）与两条分析口径（**TSC–TOI**、**熟悉度/熵**）落到 AssocVTC，回答：

> **「token 数随场景精度自适应」在本项目数据与架构上，到底值多少？**

结构前提（ANALYSIS §0）：ALIT 的**解码器并行无状态、循环在编码器**；本仓库**解码器顺序循环 + 画布 carry（BPTT）、编码器单次前向**——镜像关系，故**只借机制与实验设计，不借解码器**，也不引用 ALIT 的数字做对比（PLAN §9.2）。

## 4. E-A2 自监督 TSC：等平均 token 数对照

### 4.1 方法

对每图取**最小** t 使 `L1_255[t] ≤ τ`，读窗口 hi+1 即该图 token 数；扫 τ 得曲线，再与固定 step {3,5,7,8} 做**等平均 token 数**配对（密集 τ 曲线插值，核心口径）。
**判据（PLAN §8）**：等平均 token 数下自适应显著优于固定步（**>0.10 px** 且方向一致）⇒ 成立；复现 batch-0 天花板 ⇒ PSNR 口径结案，判决权交 E-C1。

### 4.2 结果（来源：`tsc_stdattn_rec.json` / `tsc_linattn_rec.json` / `domain_ladder.json`）

| step5（35） | **+0.3272** | −0.9218 | **+0.8541** | +0.2563 | +0.2351 |

**预算配对质量**（最近 τ 网格点的 `budget_rel_gap`）：step3 **4.37%**、step5 0.19%、step7 1.21%、step8 2.75%（全部 ≤ 4.4%，`tsc_stdattn_rec.json → matched_nearest_tau`）。

### 4.4 诚实边界（PLAN §3 E-A2 + §9）

- **PSNR/L1 不是验收**：本判决只关闭「**信息保持口径**下的自适应 K」；**不能**据此否证 §0.1 的动机（§9.3）。
- **等平均 token 数（不是等最大）** 是 ALIT Fig.6 的正确读法；本表用密集 τ 曲线插值（gap 已在最近网格点口径核到 ≤4.4%）。

### 6.4 诚实边界（PLAN §3 E-A4、ANALYSIS §5）

1. **弱代理 ≠ 感知复杂度**：JPEG 大小/边缘密度/首步 L1 都不是 ALIT 用的 SAVOIAS 人标注（0–100）。**ρ 显著不构成对 ALIT 熵假设的证明**（PLAN §8 原文）。
2. **`best_step` 目标在此 ckpt 上退化**：96.98% 的图最优步都是 step7（§3）⇒ ρ≈0 是**目标无方差**造成的，**不能**当作「复杂度不相关」的证据；也不能因为 needed_step 目标显著就声称 best_step 也相关。
3. **`needed_step` 目标带半机械成分**：τ 取的是该域末步 L1 的**中位数**（一个绝对阈值），误差水平天生更高的图自然需要更多步；而 `first_step_L1` 作为代理又与被预测的 `L1` 同源 ⇒ 部分**循环**。这条在报告里不能省。
4. 单种子；ρ 的 CI 来自 bootstrap（n=5000/n_boot=1000），只反映抽样不确定性，不覆盖「代理选择」这一层自由度。

## 7. E-A5 z_s 冗余度（第 1 项）

### 7.1 方法

`artifacts/alit/zs_redundancy.py` 调 `metrics_linattn.zs_stats`，对 `stdattn_k64_rec` 的 `z_s`（一次前向的固定产物，n=2,000 张）统计：两两 cosine、有效秩 `exp(H(σ))`（未去均值与去均值两版）、逐 token 方差、跨 token 的均值方差。
**判据（PLAN §8）**：z_s 低冗余（有效秩高、cos 低）⇒ 成立；**有效秩 ≪ K 且 cos > 0.9** ⇒ 冗余问题仍在、E-B3 动机增强。

### 7.2 结果（来源：`zs_redundancy_stdattn_rec.json`，`stdattn_k64_rec`，n=2000）

| 量 | 值 |
|---|---|
| K / D | 64 / 448 |
| 有效秩（`effective_rank`） | **47.077**（= **0.736×K**） |
| 去均值有效秩 | 49.439 |
| 两两 cos：均值 / std / min / max | **0.2569** / 0.2558 / −0.5806 / 0.9788 |
| 两两 cos：q10 / q50 / q90 | −0.0930 / 0.2736 / 0.5860 |
| frac(cos > 0.9) | **0.00305**（0.30%） |
| 逐 token 方差（跨 D 维的均值） | 1.0092 |
| token 均值方差（跨 K） | **1.909e-07** |

### 7.3 判决

**成立（低冗余）。** 有效秩 **47.08 ≈ 0.736×K**、cos 均值 **0.257**、cos>0.9 的 token 对只占 **0.30%** —— 三个方向一致的指标都落在「**不是 K 份副本**」这一侧。按 PLAN §8，其否证侧条件是「有效秩 ≪ K **且** cos > 0.9」，本数据**两个条件都不满足**。
（运营化阈值是本报告自定的：否证 = 有效秩 <0.5×K 且 cos>0.9；成立 = 有效秩 ≥0.7×K 且 cos≤0.5 且 frac>0.9 ≤0.05；已在 `tools/alit_report.py` 与聚合表标注。）

### 7.4 对 README §0.1 / GOAL §2「576 个 z_s 是同一句话重复 576 遍」的意义（**必须显式写**）

- **反证（在 K=64 这个编码器上）**：`GOAL` §2 推论 3 的「z_s 是全局摘要的 K 份副本」在这里**不成立**——64 个 token 的方向只弱相关（cos 均值 0.257）、99.7% 的 token 对互相 cos ≤ 0.9、有效秩达到名义 K 的 73.6%。也就是说：**「冗余度」不是这个 ckpt 的主要瓶颈**；用「压掉副本」当卖点，在本操作点上缺少支撑。
- **这不是对主线结论的推翻**：该主张原本描述的是 **DINOv2 主线 / K=576** 的 `slice27_v2` 观测（README §4.1 引 `两两 cos 0.963–0.974`）。本结果是**另一个操作点（从零 13 层 std 编码器、K=64）的反例**；两个操作点的 `z_s` 生成方式、维度、K 都不同构（PLAN §9.2），**不能互相外推**。要直接检验 §0.1 的寄存器冗余，需要在主线 K=576 ckpt 上跑同一组 `zs_stats`（本报告未做，列入未完成项）。
- **`token_mean_var = 1.9e-07` 的读法（防止过度解读）**：它只说明 64 个 token 的**逐 token 均值（跨 D）几乎相同**；而本编码器在返回 `z_s` 前对整段序列做了 `self.norm = nn.LayerNorm(dim)`（`model_v2_linattn.py`，`seq = self.norm(seq)` 后再切 `z_s`），**逐 token 在最后一维上被归一化** ⇒ 该量被机械地钉在 ≈0 附近，**不是**独立证据。真正有信息量的是方向类统计（cos / 有效秩 / frac>0.9）。措辞上应写「**均值同置是 LayerNorm 的下游效应；方向层面没有高冗余**」。
- **低冗余 ≠ 高信息密度**：token 之间方向不同，也可能各自携带无用信息。密度主张仍需任务保真/Phase 2 证据（README §0.1 边界）。

### 7.5 对 E-B3 动机的方向

PLAN §8 写的是「有效秩 ≪ K 且 cos > 0.9 ⇒ 冗余问题仍在，**E-B3 动机增强**」。我们拿到的是**相反侧**（低冗余）⇒ 按同一逻辑，**E-B3（逐轮新增记忆）的动机被削弱**：后步读不到新信息，若主要瓶颈真在「键不足」，那也应该已经体现在冗余度上，而这里没有。
**决策（Lead 2026-10-16）**：仍然照 PLAN 跑 E-B3，把它当作**判决实验**而不是假设验证——因为 (a) A 阶段只覆盖零训练/像素口径，(b) B3 改的是信息通路（新增键），零训练无法替代，(c) 我们需要一个可写进报告的明确否证或成立，而不是停在「动机推测」。

### 7.6 诚实边界

- **注意力熵（第 2/3 项）未做**（PLAN §9.7）：本节的结论**只覆盖 z_s 冗余度**，不能声称「注意力随迭代不专精」。
- 单种子；n=2,000 张（`--num_images 2000`），非全量 5,000。
- z_s 是**一次前向的固定产物** ⇒ 本实验无法回答「随迭代的专精」（PLAN §3 E-A5 假设）。

## 8. E-A6 边际信息分解（复现 + 细化）

### 8.1 方法

把每步边际 `Δ_t = L1[t−1] − L1[t]`（正 = 变好）与其前置累计占比、末步过冲率、类别/边缘密度分层交叉；判据是**复现旧结论**「≥88% 的降幅在前 3–4 步」（`doc/2026-09-16/ANALYSIS_ksweep_stepwise_refinement.md`）。

### 8.2 结果（来源：`tsc_stdattn_rec.json → E_A6_delta_decomposition`；域对照见 `domain_ladder.json`）

### 8.4 诚实边界

- **旧结论不可直接迁移**：09-16 的「≥88% 在前 3–4 步」来自 **224 主线 / K=576 / linear+`mean_t`** 配置；这里是 **std 编码器 + K=64 + BPTT T=8**。本实验只能说「该形态在**本配置**下不成立」，不是推翻旧结论。
- 「末步过冲率 96.98%」与 E-A1 的「96.98% 图最优步 = step7」是同一事实的两面，不是两个独立证据。
- 类别/边缘密度分层用的是弱代理（同 §6 边界），且类别层 n=50/类（IN-100 的 val 子集），**不足以支撑「某类过冲」的结论**。
- 单种子。

**成立（四臂定稿；方向与 ALIT 原版相反）。** PLAN §8 的两条同时满足，且剂量-响应单调：

- **末步 L1 改善 >0.10 px**：`b1_lastonly` **+1.2623 px**、`b1_increasing` **+0.3452 px**（最优步口径 +0.3366）；`b1_decay` **−0.6982 px（更差）**。过冲：baseline 0.0156 / increasing 0.0071 / lastonly 0.0000（**没有放大，反而缩小或归零**；`b1_decay` 放大到 0.0172）。
- **剂量-响应（ΔPSNR 降序）**：**`b1_lastonly` +2.1126 > `b1_increasing` +0.4481 > `b1_mean` 0.0000 > `b1_decay` −0.9250** ⇒ 只有「**给后步加权**」的方向有效，且越靠后越强；`b1_mean` 的平权与 ALIT 的递减都更差。
- ⇒ PLAN §8 的「四臂差 <0.10 px ⇒ 按 P3 关闭」**没有命中** ⇒ 权重方向**不关闭**。

**与 ALIT 的方向对比（必须并列写出）**：PLAN §1 第 5 条把 ALIT 的「逐迭代损失权重 `[2.5,2,1.5,1.25,1,…]`（**递减**）」列为可移植结论，并据此设计 `b1_decay` 臂。本实验**未复现该条的方向**——在本设定（224×224 / K=64 / 从零 13 层 std 编码器 / BPTT T=8 / 6 ep 热启动）下：**递减（ALIT 原版）有害**（−0.9250 dB、末步 +0.6982 px），**递增/末步加权有效**，且后步越被加权越好。机制由 §9.2 逐 step 表直接读出（前移 vs 后移），**不是事后猜测**。ALIT 的结论产生在 **256×256 + VQGAN 底座 + 每轮新增 latent** 的设定下，与本仓库**不同构**，故只报「本设定未复现该方向」，**不作跨论文比较**（PLAN §9.2）。

**代价边界（必须与判决一起读）**：`b1_lastonly` 的交付步最好，但**中间步报废**（step1 56.27 > 常量灰 50.89；step7 7.04 差于基线 6.69），与「**一条流多档 / 按预算截断**」的目标**天然冲突**（§9.2c）。⇒ 「末步 only」不能作为「变长/多档」方案的损失配方；若要兼顾交付步与可截断性，**`b1_increasing` 是本轮唯一候选**（全预算区间不劣化）。

**待补剂量点**：补充臂 `b1_tail27`（`--loss_weights 0,0,0,0,0,0,1,3`，s7 25% / s8 75%）已在计划中，**产物未到**；到位后在本节加一行「剂量-响应」小结（预期落在 `b1_increasing` 与 `b1_lastonly` 之间），**四臂判决不受影响**。

### 9.4 诚实边界

- **单种子**：0.10 px 阈值来自 PLAN §8/§9.1；+1.2623 / +0.3452 px 的效应远大于该阈值，但**仍是单种子**——若要把权重配方写进结论，建议对 `b1_increasing` 与 `b1_lastonly` 各补第二个种子。
- **过冲口径**用 step7→step8 的 `ΔL1_255`（baseline −0.01562 / increasing −0.00708 / lastonly **+1.5999**，即末步仍在真降），**不是** README §4.1 的「真阶梯」判据（那是 E-B2）。
- **`b1_lastonly` 的 100% step8 最优**说明该配方的「最优停步」自由度为零 ⇒ 它天然不支持「按图早停」（与 E-A1 的结论方向一致）。
- **跨实例混淆**：`b1_mean` 28.4094 vs 历史 `stdattn_k64_rec` 28.5823 = **−0.1729 dB**（重跑漂移 + `dec_grad_ckpt` 开关不可分离，证据见 `artifacts/alit/NOTES_run_pitfalls.md` §2.1；同配置重跑漂移口径 0.10/0.30 dB）。⇒ E-B1/B3 的对照一律用 `b1_mean`；**对历史 ckpt 的 Δ 一律不作机制归因**；**同一条边界适用于 8 臂矩阵表的 BPTT 行**。收尾 `--dec_grad_ckpt 0` 分离实验已排期。
- 本实验只测「信息保持」；权重配方的最终价值仍取决于 E-C1/E-C2（PLAN §9.3）。

> ⚠️ **PLAN §8 的三态表（成立/否证/数据不足）无法表达这种「增益成立 / 机制否证」的分裂结果**。本报告的做法是：在判决总表里显式记为 **「分裂」**（`tools/alit_report.py` 的 `V_SPLIT`），并在正文按轴分别给出三态判决；**不允许**用一个词（无论「成立」还是「否证」）概括 E-B3。

### 11.4 机制：增益来自「每步都有新信息」，不是「后续步被激活」（由逐 step 表直接读出，非猜测）

- **生长 token 从 step1 就可读**：读出集合 **3 → 19**（16 个生长 token 在第一步就进入交叉注意力的 memory），此后累计到 **192**（NOTES §3 的 `GrowthBlock` 接线核对）。
- 因此 step1 就比 `b1_mean` 好 **3.4431 px**（15.27 → 11.82）——**这是「新增可读键」的直接效果，与「后步被激活」无关**；随后各步增益单调走弱（+3.44 → +1.19），与「信息在早期一次性补足、后续步边际递减」的形态一致。
- 若真是「后步激活」，应看到 **Δ₁ 占比下降 + 后步 Δt 上升**；实测**两者都反向**（Δ₁ 升到 45.66%，step7/8 的 Δt 只有 0.36/1.60 仍远低于前期）⇒ 机制假说被否证。
- 另：`b3_grow` 的 100% 样张最优步落在 s7/s8 的比例是 74.82% / 25.18%（`b1_mean` 95.92% / 4.08%）⇒ 读满 192 个 token 也不再「普适最优」，与「每步都有新键」一致。

### 11.5 诚实边界

1. **参数未匹配（最重要的一条）**：`GrowthBlock` 新增 **1,049,600** 参数，总参数 **63.055 M → 64.104 M（+1.7%）**。**未做参数匹配的 placebo 对照**（例如同样 +1.05 M 的随机/无效模块）⇒ 只能说「增益来自**新增可读 token** 这一机制解释」，**不能宣称已排除参数量本身的贡献**。这是本实验最大的未控制变量。
2. **判据 (c) 未测**：注意力熵（E-A5 第 2/3 项）未做 ⇒ 轴 2 的否证只覆盖 (a2)(b) 两条，不覆盖 (c)。
3. **基线口径**：对照必须用同机同预算的 `b1_mean`（28.4094）；历史 `stdattn_k64_rec`（28.5823）含 **−0.1729 dB** 的重跑漂移 + `dec_grad_ckpt` 开关混淆（§9.2），只能作旁证。
4. **`stdattn_k64` 单步上界不可比**：训练预算 45 ep 从零 vs 6 ep 热启动（7.5×），`b3_grow` 距它 −0.63 dB **不代表**「已接近单步上界」的可比结论。
5. **单种子**：+2.18 dB 的效应远超噪声，但仍是 seed 0；若要写进结论应补第二个种子。
6. 本实验只测「信息保持」；E-B3 的最终价值取决于任务保真（E-C1/E-C2）。

### 11.6 与 E-B4 的关系（候选配方，详见 §12）

`b3_grow` 的**截断曲线全预算区间最好**（t=3/5/7/8 → **7.5057 / 6.3385 / 5.5065 / 5.5132**，§9.2c 的均质对照）⇒ 它是「一条流多档」的两个可行候选之一（另一个是 `b1_increasing`）；`b1_lastonly` 只在 t=8 可用。

## 12. E-B4 随机预算采样 / 「一条流多档」

### 12.1 方法

4 臂：现状（全步反传）/ **随机子集反传**（`--sample_grad_iters`）/ 臂 2 + 推理**截断到 t=3/5/7** / **专训固定档** K'=16/32/48。
**判据（PLAN §8）**：截断档与专训档在**同等平均 token 数**下差 **<0.20 px** ⇒ 「一条流多档」成立；否则必须保留「每档微调」，并在报告里写明代价。

**⚠️ 范围裁剪（2026-10-16 Lead 决定，必须照录）**：**专训固定档 K'=16/32/48 不做**——从零训练 3 个档位约 **3 × ~5 h**，超出本轮预算。因此 E-B4 的**核心判据（截断档 vs 专训档 <0.20 px）在本轮不可判**，该判据位记「**数据不足 + 成本理由**」，**不是待补、不留空**。

### 12.2 结果：截断代价已可直接量化（零额外训练）

**口径**：BPTT 链式因果 ⇒ 「只跑前 t 步」的截断输出与全链第 t 步逐位相同 ⇒ 各臂 `stepwise_*.json` 的逐 step `L1_255` **就是**截断曲线（与 §9.2c 同表，此处加入 `b3_grow`）。

**候选配方 × 等 token 预算（L1_255，越低越好）：**

| 配方（臂） | t=3（15 tok） | t=5（35 tok） | t=7（63 tok） | t=8（64 tok） | t=8 PSNR | 可截断性 |
|---|---|---|---|---|---|---|
| `b1_mean`（平权基线） | 11.413 | 8.410 | 6.692 | 6.707 | 28.409 | 参考 |
| `b1_decay`（ALIT 原版递减） | 11.236 | 8.819 | 7.388 | 7.405 | 27.484 | 中档劣化 |
| `b1_increasing`（递增） | 12.066 | 8.476 | **6.355** | 6.362 | 28.857 | ✅ 全区间不劣化 |
| **`b3_grow`（GrowthBlock）** | **7.506** | **6.338** | **5.506** | **5.513** | **30.591** | ✅✅ **全预算区间最好** |
| `b1_lastonly`（末步 only） | **48.446** | **30.908** | 7.045 | **5.445** | **30.522** | ❌ 只在 t=8 可用（t≤6 逼近/劣于常量灰 50.892，t=7 输基线 0.35 px） |

**可用的候选配方 = 两个**：

1. **`b3_grow`**：交付步 **30.5910 dB**（vs `b1_mean` **+2.1815 dB**），且 **t=3/5/7/8 全预算区间最好**（7.506 / 6.338 / 5.506 / 5.513）⇒ 「一条流多档」的首选；
2. **`b1_increasing`**：交付步 28.8575 dB（+0.4481），t=3/5 比基线差 0.65/0.07 px、t=7/8 反超 0.34/0.35 px ⇒ **唯一在纯损失侧改动下全区间不劣化**的配方（不新增参数，无 §11.5 的参数混淆）。

`b1_lastonly` 只在 t=8 可用（§9.2c）⇒ **不能**作为变长/多档方案；`b1_decay` 与 `b1_mean` 在各档均被上述两个候选支配。

> ⚠️ 这些是**截断代价**（同一模型在不同预算下的可用性），**不是** PLAN §8 的「截断档 vs **专训档** <0.20 px」判据——后者因专训档裁剪而**不可判**（见下）。

**正式 E-B4 臂仍数据不足（成本裁剪 + 未到位）。** 需 `eval_b4_sg.json` 与**截断推理的评测产物**（现有脚本按固定步集评测，截断档需要单独的评测调用）；`eval_b4_k{16,32,48}.json` **按上条裁剪不做**。

### 12.3 判决

**数据不足（成本理由：专训档 K'=16/32/48 裁剪不做 ⇒ PLAN §8 的 <0.20 px gap 不可判）。** 但**代价侧已给出强对照**：`b3_grow` / `b1_increasing` 是两个「一条流多档」可行候选，`b1_lastonly` 被截断代价排除（§12.2）。若后续要跑 E-B4 臂，应在这两个候选上做截断评测，并以它们（而非 `b1_mean`）作为等预算对照基准。

### 12.4 诚实边界（PLAN §9.5）

- **预期为负**：`doc/2026-09-22/REPORT_slice1_224.md` 已证「删一步的代价摊到所有后续步」（BPTT 是串联草稿链）；本轮数据（§12.2）量化了这一点，且**否掉了「末步 only + 截断」的组合**。
- **截断 = 全链同值的前提是「链式因果 + 无 carry 重置」**：本仓库 BPTT 满足；若将来改成 E-B3 方案 b（无 carry 的独立档解码），截断曲线不再等于逐 step 曲线，必须重跑。
- **专训档的结论缺席**：没有 K'=16/32/48 的专训对照，「截断档落后专训档多少」这个问题本轮**没有答案**；只能说「哪些配方在截断下仍然可用」。
- 单种子。

### 13.4 诚实边界（必须照录）

1. **分类线性探针 ≠ Phase 2 生成任务**：它只测「z_s 前缀中类别可线性读出的信息」，不能替代 GOAL §2 的 caption/幻觉口径（E-C2）。
2. **探针质量边界（本轮最重要的一条）**：`train_top1` 0.45–1.00（`_cls` 变体 = 1.0000）vs `val_top1` 0.049–0.112（chance = 0.01）⇒ 严重过拟合 + 线性可分性差；**val 曲线非单调**（14 步进里 3~5 次下降）。因此 `indistinguishable` 只能读作「**该探针分辨力下测不到差异**」，**不能说「自适应 = 固定 K」**，更不能据此判 E-C1 成立或否证。工具自己的 `honesty` 也写了同一条（"曲线非单调时先看各档 train top-1 再谈科学结论"）。
3. **等平均 token 数**口径：自适应逐图 `k_i` 必须与「平均 token 数相同」的固定档比较（主臂 mean_k = 37.9014 ≈ 0.592×K），**不能**与固定 K=64 或等最大 token 数比（ALIT Fig.6 的正确读法）；插值存在格点误差，故 json 同时报最近格点值。
4. **oracle 上界只量化 gap**：`any_k_correct_rate = 0.2968` 是「知道标签时每图取最省 token」的不可实现上界，不是策略；TSC（重建 L1）与 TOI（分类）**不必然对齐**，本结果正显示这个 gap 很大。
5. **单种子**；paired bootstrap CI 只覆盖抽样不确定性；工具判据是 ±0.5 pp。
6. 即使 E-C1 将来判「成立」，也只是任务保真口径的第一步——本项目一个 caption/幻觉指标都没跑过（README §0.1）。

## 14. 结论与对 README §0.1 的影响

### 14.0 决策记录：A 阶段否证，**为什么仍然主动继续 B 阶段**（2026-10-16）

**结论先行（Lead 2026-10-16 原话口径）**：**B 阶段继续是 Lead 的主动决策（非遗漏）**——依据 = **B1/B2/B3 判决的是 README §4.1「让后步真干活」这个独立未决问题**（P3 损失加权 / P1 区域损失 / ALIT 记忆增长），A 阶段的否定结论**不能替它们判决**，且成本可承受。停止/收敛条件 4 条保留（见本节末）。

**A 阶段的判决（§3–§8，全部按 PLAN §8）**：E-A1 **否证**、E-A2 **否证**、E-A3 **否证**、E-A6 **否证**；E-A4 成立（仅在弱代理 + 半机械目标上）；**E-A5 成立（低冗余）⇒ E-B3 的动机方向被削弱**。

按 PLAN §3 前言「若 A 阶段就给出否证，B/C 阶段直接停，节省 ~30 GPU·h」，本应止损。**决定继续 B（Lead 2026-10-16），理由与边界如下——这是主动决策，不是默认继续**：

1. **A 阶段只覆盖「信息保持 / 自监督」口径**：PLAN §3 明确把唯一验收口径定在 E8/Phase 2（PLAN §5、§9.3），E-A 的四个否证**不能**外推到任务保真。
2. **E-C1 的探针分辨力不足**：`indistinguishable` 伴随 train↔val 巨大 gap（§13.2/§13.4）⇒ 它**既不能判成立也不能判否证**，也就是说「自适应 K 在任务保真上值多少」这个问题**在 A 阶段结束时仍然没有答案**。止损的条件没有满足。
3. **B 阶段测的是 A 阶段原理上测不到的东西**：A 全是零训练/固定 ckpt；E-B1 改损失权重、E-B2 改梯度分区、**E-B3 改信息通路（新增键）**、E-B4 改训练预算采样。尤其 E-B3 是 README §4.1 未决问题（「后步真干活」）的唯一「改信息通路」手段，零训练无法替代。
4. **E-A5 的低冗余结论把 E-B3 从「假设验证」变成「判决实验」**：动机削弱不等于结论，而一个明确的成立/否证对项目更有价值（§7.5）。
5. **成本可控且已有可比基线**：B 臂单臂 1.6~2.5 h、串行单机；基线 `b1_mean`（28.4094 dB，同机同预算）已到位，B1/B3 的配对已有干净对照（§9.2 的 −0.173 dB 混淆边界已写明）。

**停止/收敛条件（写在前面，避免无界投入）**：① E-B1 四臂差 <0.10 px ⇒ 按 P3 关闭权重方向——**该条件未命中**：四臂给出单调剂量-响应（`lastonly +2.113` > `increasing +0.448` > `mean 0` > `decay −0.925`，§9.3）⇒ 权重方向保留，并附带一条**代价边界**（lastonly 牺牲可截断性，§9.2c）；② E-B3 三项判据全不成立 ⇒ 关闭「记忆增长」方向并写明「任务同构是主因」——**该条件未命中（部分命中）**：recon 增益轴**成立**（+2.1815 dB，方向不能关闭），机制轴（后步激活）**否证** ⇒ 记为「分裂」（§11.3）；被关闭的只是「后步激活」这一**机制解释**，不是「新增可读 token」这条通路；③ E-B4 专训档已裁剪，只做**截断代价量化**，不追求「一条流多档」成立；④ E-B2 若臂跑完仍缺 ①③ 判据，则明确记为「数据不足 + 产物缺口」，不再追加训练。

### 14.1 现在能下的结论

1. **E-A0 成立**：四臂逐位复现 + 回归门 PASS（`baseline_four_arm_eval.json`、`gate_diff_stdattn_rec.json`）。
2. **E-A1 否证（两臂）**：std 臂 96.98% 图最优步 = step7、停步熵归一化 0.065；oracle 上界只值 **+0.00016 px**（lin 臂 +0.0029 px）⇒ 像素口径下「按图选停步」没有可利用自由度。
3. **E-A2 否证**：等平均 token 数下自适应**更差**（std up to +0.3272 px / −0.92 dB；lin up to +1.2060 px）⇒ 重建损失作 TSC 准则在本项目数据上不划算。判决权交 E-C1。
4. **E-A3 否证**：max\|Δμstep\| = 0.0247 步；且**远距 OOD 反而更少步**（ADE20K step7 L1 5.9722 < IID 6.5973）⇒ 熟悉度假设不成立。
5. **E-A5 成立（低冗余）**：有效秩 0.736×K、cos 均值 0.257、frac(cos>0.9) 0.30% ⇒ 「K 份副本」在 K=64 这个编码器上不成立（§7.4 的边界一并读）。
6. **E-A6 否证**：≥88% 在前 4 步不成立（step4 = 65.09%），且 Δ_t 非几何衰减（t2 < t3）。
7. **E-A4 成立但极弱**：只在 needed_step 目标上、且在三条边界下成立（§6.4）。
8. **E-B1 成立（四臂）且方向与 ALIT 相反**：剂量-响应 **`b1_lastonly` +2.1126 dB / 末步 +1.2623 px > `b1_increasing` +0.4481 / +0.3452 > `b1_mean` 0 > `b1_decay` −0.9250 / −0.6982**；`b1_decay`（ALIT 原版递减）是**质量前移**（step1 −1.089 px、之后全变差）。⇒ **PLAN §1 第 5 条未复现，方向相反**。**代价**：lastonly 的中间步报废（step1/2 高于常量灰），**不能用于「一条流多档」**；`b1_increasing` 是唯一全预算区间不劣化的配方。基线 `b1_mean` = 28.4094 dB（比历史 28.5823 低 **0.1729 dB**，含重跑漂移 + `dec_grad_ckpt` 开关，**不可归因**）。
9. **E-B3 = 分裂（增益成立 / 机制否证）**：`b3_grow` 同预算 **+2.1815 dB**、末步 **−1.1940 px**，截断全区间最好（t=3/5/7/8 = 7.506/6.338/5.506/5.513）⇒「**新增可读 token**」这条通路有效；但 **Δ₁ 占比 25.43%→45.66%（升）**、后步 Δt 均值 0.772→0.322（降）⇒ ALIT 的「后步激活」机制假说**否证**，增益来自「每步都有新信息」（生长 token 从 step1 就可读，step1 即好 3.4431 px）。**最大未控制变量 = 参数量**（+1.0496 M / +1.7%，无参数匹配 placebo 对照）。
10. **E-C1 = 数据不足（探针分辨力不足）**：三臂 27 个扫描行的 Δpp 全部跨 0（主臂 +0.2723 pp，CI [−0.3713, +0.9776]），无一行达 ±0.5 pp 判据；探针 `train_top1` 0.45–1.00 vs `val_top1` 0.049–0.112 ⇒ **只能说「该探针测不到差异」**；oracle 上界 0.2968 表明 TSC–TOI gap 很大。

### 14.2 对 §0.1「token 数随场景精度自适应」的影响（谨慎表述）

- §0.1 第 2 条（自适应 token 数）当前仍是**只有动机、没有实现**的目标设想。本轮给出了**第一批实测**：在**信息保持口径**下，A 阶段四项否证（E-A1/A2/A3/A6）**削弱**了「按图自适应 K 能提升保真」的期待，其中 E-A2 是负向（等预算更差）而非中性。
- **但这不是对 §0.1 的最终否证**：唯一验收是 E-C1/Phase 2，而 E-C1 的分类探针分辨力不足（§13.4）⇒ 结论只能是「任务保真上**尚无定论**」。因此本报告**不修改** §0.1 正文口径，**不推翻** GOAL §4.1。
- **E-A5 是另一个方向的收获**：在 K=64 这个编码器上，z_s **不是**「同一句话重复 K 遍」（有效秩 0.736×K、cos 0.257、frac>0.9 0.30%）⇒ 至少在这个操作点上，「压冗余」不是主要矛盾。该反证的适用边界见 §7.4（与 K=576 主线不同构）。
- **对 GOAL §2 推论 3 的直接检验仍未做**（需在主线 K=576 ckpt 上跑 `zs_stats`）——列入未完成项。

### 15.1 执行注意（工装坑，来源 `artifacts/alit/NOTES_run_pitfalls.md` §1）

- **`train_linattn.py --batch_size` 默认是 128，不是 B 协议要求的 64**：漏写时冒烟实际跑 bs128 + BPTT T=8 ⇒ `torch.OutOfMemoryError`（31.4/32 GiB）。所有 B 臂必须显式 `--batch_size 64`（`run_alit_b.sh` 已固定）。
- **`--smoke --limit < batch_size` ⇒ 空训练 loader**（`drop_last=True`）：实测跑到 `epoch=453, step=0` 而不报错，约 20 分钟空转。规避：`--limit ≥ 2 × batch_size`。
- **VRAM 修正事实**：bs64 + BPTT T=8 时，`--dec_grad_ckpt 1` 峰值 **23.3–24.0 GB**、`--dec_grad_ckpt 0` 峰值 **24.0 GB** ⇒ 两者都能在 32 GB 卡上跑；**此前「关 grad-ckpt 会 OOM」是 bs128 造成的，不成立**（所以 §9.2 的收尾分离实验可行）。b1_mean 训练全过程 23.8 GB、126–129 img/s、11,406 步 94.9 min。
