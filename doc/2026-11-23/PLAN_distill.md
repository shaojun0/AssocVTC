# 计划：参考 ALIT 做"蒸馏"——两种含义、哪种值得做、怎么做

- 时间：2026-11-23
- 起点：`k256x12_t8`（L1 14ep，256²，3072 values/图，末步 22.67 dB / rFID **86.50**）
- 目标：把 rFID 从 86.5 压到 ≤30（Q1 门槛），且不放弃"单模型多速率"这一卖点
- 一句话：**蒸馏是当前唯一有理论依据且有预算走通的路线；但必须先分清"哪种蒸馏"，并先花 15 分钟量一个天花板。**

---

## 0. 先分清：ALIT 里的"蒸馏"指的是什么

> **⚠️ 2026-11-23 更正（读官方代码后）**：本节的"ALIT **没有** teacher-student 知识蒸馏"是**错的**。
> ALIT 的 stage-1（`train_stage="latent_distillation_pretrain"`）就是标准蒸馏：把 **frozen base
> tokenizer 的 latent / codebook index 当回归目标**，像素用 **teacher 自己的 decoder** 渲染，
> 且 stage-1 里**没有任何像素损失**（stage-2 才用 GAN+LPIPS+L1 渲染微调）。
> 逐行对比、我们这一臂为什么白跑、以及改进点见 `NOTES_kd_vs_alit_code_20261123.md`。
> 下文 §1–§2 的"跨模型输出蒸馏"路线判断仍然成立，但"ALIT 不做蒸馏"这个前提作废。

ALIT（Duggal et al., *Adaptive Length Image Tokenization via Recurrent Allocation*,
arXiv:2411.02393 / ICLR 2025）**没有 teacher-student 知识蒸馏**。它被称作 "distillation" 的是
**stage-1 的 2D→1D token 转置机制**：

- 把 2D patch token 与一串 1D token 拼接，过一个 full self-attention encoder ⇒ "蒸馏"出 1D codes；
- 再用一个 append 了 2D masked token 的 decoder 解回 2D token（把转置当 masked 重建来解）；
- 对变长重复上述过程（recurrent allocation）⇒ 一个模型输出任意长度的 token 序列；
- 像素重建用 VQGAN + CE on discrete tokens，训练后期再加对抗损失；IN-100 Stage1 200ep + Stage2 200ep。

所以"参考 ALIT 去蒸馏"有两种读法，收益完全不同：

| 读法 | 做什么 | 对我们的收益 | 判断 |
|---|---|---|---|
| **A. 跨模型蒸馏**（ALIT/VAE/扩散当 teacher，把强解码器先验搬进我们的网络） | 输出级监督，L1/L2 到 teacher 的输出 | **直接压 rFID**，是唯一有望从 86.5 到 ≤30 的手段 | ✅ 主线，值得做 |
| **B. 复刻 ALIT 的 2D→1D 蒸馏机制** | 把现在的 SVD 线性瓶颈换成"注意力蒸馏转置" | 同速率 PSNR 涨 0.5–1.5 dB；支持变长/自适应 | ⚠️ 有论文价值，但**不治 FID** |

下面主要写 A，末尾给 B 的评估。

## 1. 为什么蒸馏这次"有戏"，而前面四次都失败

### 1.1 决定性数字：**同值数下，ALIT 在每一个速率点都比我们好 8–10 倍，且倍数与速率无关**

我们 `k256x12` 的 8 个速率点 vs ALIT-S Stage2（IN-100，256²，Table 3；ALIT-equiv token = values/12）：

| 我们的 values | 384 | 768 | 1152 | 1536 | 1920 | 2304 | 2688 | 3072 |
|---|---|---|---|---|---|---|---|---|
| ALIT-equiv token | 32 | 64 | 96 | 128 | 160 | 192 | 224 | 256 |
| **我们 rFID** | 178.07 | 146.43 | 126.30 | 112.26 | 101.55 | 93.58 | 89.31 | **86.50** |
| **ALIT-S rFID** | 22.57 | 16.17 | 13.30 | 11.69 | 10.22 | 9.30 | 8.55 | **8.25** |
| 倍数 | 7.9× | 9.1× | 9.5× | 9.6× | 9.9× | 10.1× | 10.4× | **10.5×** |

倍数几乎是平的 ⇒ **差距不是"速率不够"**。另外按名义比特率算（我们连续 12 维 bf16 = 192 bit/token，
ALIT VQ 12 维×32 级 = 60 bit/token），**我们其实比 ALIT 多花 3.2× 的比特，还差 10.5×**。
⇒ 瓶颈是**解码器先验 + 训练目标 + 预算**，而不是信息量。

### 1.2 前面四次为什么必然失败，而蒸馏不落进同一个坑

| 尝试 | 损失类型 | 为什么失败 |
|---|---|---|
| L2 | 逐像素，目标=GT | 高斯 NLL ⇒ 条件均值 ⇒ 更糊 |
| VGG 感知 L1 | 特征级，目标=GT 特征 | 只能"更平滑地接近 GT"，不携带"该长什么纹理"的信息 |
| PatchGAN | 对抗，无显式目标 | 1100 步 / 3h 完全不够，且破坏累计解码结构 |
| batch rFID | 分布统计，n=8 | 秩-n−1 零空间 + 采样偏置（见 `NOTES_rfid_loss_feasibility_20261123.md`） |

四者的共同点：**梯度信号来自"目标分布"，而目标分布在 3072 values 下是不可达的**（GT 的纹理细节
根本传不过来），于是任何损失都只能把输出拉向某个"平均解"。

蒸馏换了一个目标：**学生不追 GT，追 teacher 的输出**。而 teacher 的输出是**同为 3072-ish 值数的解码器
真能产生的东西**（ALIT 8.25 就是证明）。所以：

- 目标从"不可达"变成"可达"（同一个 R-D 点上 teacher 已经做到了）；
- 目标是**确定性**的（一图一 output），不是分布统计 ⇒ 没有 batch-size 偏置、没有秩零空间、没有对抗不稳定；
- 损失形式仍是 L1/L2，和现有训练器完全兼容（复用 `_pred01/_tgt01` 那个挂载点即可）。

即：**蒸馏 = 把 teacher 400 epoch + 对抗训练出来的解码器先验，压缩成我们 2–3 epoch 的监督信号。**

## 2. 方案 A：输出级蒸馏（推荐）

### 2.1 三种 teacher，按"可落地性 × 上限"排

| teacher | 256² 下 rate | 框架 / MUSA 风险 | 预期 `FID(real, teacher(real))` | 蒸馏后 rFID 现实预期 |
|---|---|---|---|---|
| **SD-VAE**（`stabilityai/sd-vae-ft-mse`，4×32×32 = **4096** 值） | 4096（≈我们的 1.33×） | 纯卷积 + torch，**低**（MUSA 几乎肯定能跑） | 待测（量级 10–20） | **25–45** |
| **ALIT-S/B Stage2** | 3072（**完全同速率**） | 仓库框架未知，**高**（若是 JAX 则 MUSA 无解，只能 CPU 离线） | **8.25**（已发表，非配对 FID） | 15–30 |
| **VQGAN f16 / LlamaGen VQ** | 65536+（20× 我们） | torch，中 | ~5–10 | 20–35，但 rate 差 20× ⇒ 只能当"上界参考"，不适合当主路线 |
| **SD-Turbo img2img**（post-filter，强度 0.15–0.25） | 无 rate 约束 | diffusers，**高**（计划里已标注可能不通） | 可直接把 rFID 压到 20–40 | 20–40，但 PSNR 明显掉，且"tokenizer"故事变弱 |

**首选 SD-VAE**，理由：
1. 它是 **L1 + LPIPS 感知 + PatchGAN 对抗** 训出来的（LDM 论文 §3.1），也就是我们**买不起的那套配方**的产物；
2. rate 与我们在同一量级（4096 vs 3072），蒸馏目标在物理上是可达的；
3. 纯卷积、torch、权重 335 MB、可离线跑 —— 不依赖 diffusers，不踩 MUSA 的扩散栈坑；
4. 目标分支可以 **on-the-fly 算**：`t = D(E(x))`，8 张 256² 的卷积前向，**几乎不增加步时**（无需缓存 126k 张图）。

ALIT 的权重若可拿到，是更强的 teacher（同一速率、8.25），作为方案 A2 并列排期。

### 2.2 训练配方（最小改动）

在现有 `train_linattn.py` 里已经有 `_pred01 / _tgt01` 挂载点（perc / rfid / gan 都挂在这里）：

```
loss = 1.0 · L1(所有 8 步,  x)          # 保留：R-D 曲线与结构锚，不能丢
     + 1.0 · L1(末步 F_hat,  t)          # 新增：KD 目标，t = teacher(x)，只挂末步
```

- **只挂末步**：若 8 步全挂 teacher，早期少 token 的步会被迫"装锐"，重演 step8 破单调性的问题；
- 保留 L1-to-x（权重可降到 0.5）防止漂移出"重建"语义；
- 可加 `0.1·L2(末步, t)` 或 teacher 特征匹配，但**先不加**，单变量先看效果；
- 学习率：从 ep14 ckpt 续训，lr 2e-5 余弦（比上次 L2 的 5e-5 更保守，因为这是换目标）；
- 预算：**2 epoch ≈ 2.6 h** 先看趋势，有效再补到 3–4 ep。评测每次 +8 min。

### 2.3 必须先过的决策门（P0-c，15 分钟，无训练）

**在动任何训练之前，先量 teacher 自己的重建 FID**：
对 IN-100 val 5000 张，算 `FID(real, teacher(real))`。

| 结果 | 决策 |
|---|---|
| ≤ 25 | 走蒸馏：目标可达，学生现实能到 25–45 |
| 25–45 | 谨慎：学生最多到 45–70，收益有限，但仍可能比 86.5 好 |
| > 45 | **不走**：说明该 teacher 在 IN-100 上也没能提供低 FID 的重建先验，改换 teacher 或回 refiner 路线 |

这一步同时也给出"同速率的 FID 天花板"数字，是论文里**必须**有的一行（对比 ALIT 8.25 时用来说明
"我们的架构 + 强 teacher 先验能到多少"）。

## 3. 方案 B：复刻 ALIT 的 2D→1D 蒸馏机制

### 3.1 我们现在是怎么做 2D→1D 的

`zs_proj / mem_proj` + **SVD 秩截断 warm start**：把全宽 2D 特征线性压到每个 1D special 的 12 维。
这是**线性、无学习**的压缩，配合 3 epoch 微调。

### 3.2 ALIT 的做法

`[1D tokens ; 2D tokens] → full self-attention encoder → 1D codes`，
`[1D codes ; masked 2D tokens] → decoder（解 masked 重建）→ 2D tokens`。
好处：(i) 1D codes 是非线性"计算"出来的摘要，不是线性投影；
(ii) 天然支持变长（recurrent allocation / 自适应停止），这是他们论文的主卖点。

### 3.3 对我们的收益与代价

- 收益：同速率 PSNR 可能 +0.5–1.5 dB；拿到"自适应长度"这个论文卖点（可以做一个
  "按图片复杂度决定用几个 token"的实验，和 ALIT 的核心 claim 对齐）。
- 代价：要动瓶颈结构（`zs_proj/mem_proj` → 一个小 attention 转置模块），并且要重新训；
  与"8 步 cumulative decode"的现有实现要重新对齐（ALIT 是逐次 append token，我们是窗口逐步放开，
  两者可以映射，但要小心）。
- **它不治 rFID**：ALIT 的低 FID 来自 VQGAN + 感知 + 对抗 + 400ep，不来自转置机制。

**建议**：方案 B 放到方案 A 有结果之后作为"架构卖点"的补充，不要现在做。

## 4. 风险与诚实边界（写进论文前必须想清楚）

1. **这是一次"沿 R-D-P 曲线移动"的操作**。学生不再逼近输入图，而是逼近 teacher 的输出 ⇒
   PSNR/SSIM 会掉（预期 −0.5 ~ −1.5 dB），LPIPS 会好。必须**同时报 PSNR + SSIM + LPIPS + FID**，
   并且给出同模型无 teacher 的对照点。
2. **teacher 只在训练时用、推理时不用**，且 teacher 的输入是 **x（或学生的重建）而不是 GT 之外的信息**。
   若让 teacher 看 GT 再生成目标（img2img from GT），就是作弊 —— 这条边界要写清楚。
3. **评审风险："你只是把别人的先验搬过来"**。缓解：给出参数量表（我们 480M vs teacher 84M）、
   同 rate 无 teacher baseline、以及"蒸馏后仍保留单模型 8 速率"这一架构差异。
4. **不要在已收敛模型上做长尾微调就宣称胜利**：上面四次负结果都证明"事后小步微调"不行。
   这次是**换目标重训 2–3 ep**，且必须从一开始就监控 PSNR 掉多少、rFID 降多少（Pareto 前沿）。
5. **蒸馏 gap 是真实的**：学生 3072 值 vs teacher 4096 值 + 14ep vs 200ep，别指望追平 teacher。

## 6. 与已有计划的关系

- `PLAN_refiner_roadmap_20261122.md` 的 P0-b（预训练后处理天花板）与本计划的 **P0-c 是同一件事的两种版本**：
  P0-b 用扩散 post-filter（更强、更冒险），P0-c 用 SD-VAE 输出（更弱、但能直接当监督目标）。
  **先跑 P0-c**：15 分钟就有数字，且它的输出能直接当 P1-kd 的监督信号，不浪费。
- refiner 路线讲的是"**后处理**把糊变锐"（推理时多一个小网络）；蒸馏路线讲的是"**把先验装进主解码器**"
  （推理时零额外成本）。后者对"单模型多速率 tokenizer"这个故事更干净，也更省推理 FLOPs。
- 两者不冲突：KD 训完若还不够，再在其上加 refiner 是自然叠加。
