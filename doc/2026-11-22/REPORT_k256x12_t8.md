# AssocVTC 256 token × 12 dim（3072 值/图）+ 8 步循环解码 vs ALIT-IN100

日期：2026-11-21 11:13 → 2026-11-22（24h 单次实验，4× MTT S4000 48GB）
目标：在**不改循环解码架构**的前提下，把 8 步 cumulative 解码的 rFID 尽量压低，与 ALIT（arXiv:2411.02393）Table 3 逐点对照。

---

## 1. 设置：把速率与分辨率口径都对齐 ALIT

| 项 | 取值 | 与 ALIT 的关系 |
|---|---|---|
| 输入分辨率 | **256×256** | ALIT Stage-2 主表同为 256² |
| patch | 16 → N = 256 token | — |
| 特殊 token 数 K | **256** | — |
| 每 token 瓶颈维 zs_dim | **12** | ALIT 1D token dim = 12 |
| 速率 | **256 × 12 = 3072 values/图** | 恰为 ALIT 最高速率点（256 token × 12） |
| 解码 | `RecurrentOutputQueryDecoder` **T=8，cumulative** | **架构未改**（唯一硬约束） |
| 8 步窗口 | 32, 64, 96, 128, 160, 192, 224, 256 | 每个步数 = ALIT Table 3 的一个点 |
| 参数 | 480.6M（enc 244.8M / dec 235.8M） | ALIT-S ≈ 173M（不同量级，见 §5） |
| 训练 | 从零，ImageNet-100（121,689 train / 5,000 val），batch 128 × 4 卡 | ALIT 用 IN-1k+IN-100，≥400 ep |

关键点：因为 T=8 是**同一个模型**在第 k 步输出 k×32 个 token 的重建，所以**一个 ckpt 直接给出 8 个 rFID 点**，与 ALIT 的 8 个速率点一一对应，无需训练 8 个模型。

rFID 协议：官方 FID-InceptionV3(pool3, 2048d)、resize 299、[0,1]→[-1,1]、uint8 量化后内存内计算（等价 pytorch-fid），5000 张 val 图，无 PNG 落盘（`fast_rfid.py`）。

## 3. 阶段 2：L1 + batch rFID 损失 —— **未完成（工程故障）**

计划：从阶段 1 best 续训 2.4h，加 `--rfid_weight 0.05`。
实际：启动 15s 即崩，`load_init_from` → `_init_bottleneck_warm_start` 对**本身已是瓶颈结构**的 ckpt 又做了一次 SVD，把 `(12,12)` 的 `Vh_d` 拷进 `(12,1248)` 的 `zs_proj`：

```
RuntimeError: The expanded size of the tensor (1248) must match the existing size (12)
  at non-singleton dimension 1.  Target sizes: [12, 1248].  Tensor sizes: [12, 12]
```

修复（已落盘 `train_linattn.py`，2026-11-22 fix）：`mem_proj` 的输入维 == zs_dim 时判定"源 ckpt 已含瓶颈"，跳过 SVD warm start：

```python
if key in sd:
    W = sd[key].float()
    if int(W.shape[1]) == d:      # 源 ckpt 已是瓶颈结构 → 原样加载即可
        _p(f"[init_from] zs_dim={d}: 源 ckpt 已是瓶颈结构，跳过 SVD warm start")
        return
```

代价：24h 预算里这一环撞在阶段 1 结束的临界点，修好后时间只够跑一个阶段 ⇒ 阶段 2 被**阶段 3（感知损失）取代**（同为"改损失"路线，但感知损失对 rFID 的直接作用更明确，且已被证明在 L1-only 过平滑的模型上有效）。阶段 2 的 rFID-loss 消融留作后续工作。

## 4. 阶段 3：+ VGG16 感知损失（压 rFID 的主力）

设置：从阶段 1 `ckpt_best`（22.61 dB）续训，`--perc_weight 0.15`、VGG16 `relu1_2/relu3_3/relu4_3`（layer 3,8,15）、输入 resize 256、ImageNet 归一化、目标分支 no_grad；lr 6e-5，3.0h（约 2 个 epoch，batch 128×4 卡）。

### 4.1 结果：**感知损失让 rFID 变差（负结果）**

训练 3.0h（2147 步 ≈ 2.26 ep，185 min，best val 21.83 dB），8 点对比：

| step | tokens | L1: PSNR / rFID | +感知: PSNR / rFID | ΔrFID |
|---|---|---|---|---|
| 1 | 32 | 19.04 / 178.07 | 18.63 / 185.21 | **+7.14** |
| 2 | 64 | 20.43 / 146.43 | 19.87 / 155.58 | +9.14 |
| 3 | 96 | 21.26 / 126.30 | 20.69 / 135.68 | +9.38 |
| 4 | 128 | 21.80 / 112.26 | 21.24 / 120.32 | +8.06 |
| 5 | 160 | 22.15 / 101.55 | 21.60 / 109.52 | +7.96 |
| 6 | 192 | 22.42 / 93.58 | 21.85 / 100.36 | +6.78 |
| 7 | 224 | 22.58 / 89.31 | 22.00 / 91.90 | +2.59 |
| 8 | **256** | **22.67 / 86.50** | **21.91 / 95.53** | **+9.03** |

**8 个速率点全线变差**，PSNR 掉 0.76 dB、rFID 涨 9.03（-10%）。视觉上（`artifacts/k256x12_t8/perc1/s2/samples/epoch003_val.png`）重建比 L1 版本**更平滑**、色彩偏移更明显。

**为什么无效**（这是本实验最有价值的诊断）：

1. **VGG 特征 L1 本身仍是"期望值"损失**。它在特征空间求 L1 的均值，对"模型无法精确匹配"的分量依然是**平均掉**——只是把平均对象从像素换成了 relu1_2/relu3_3 特征。FID 惩罚的是纹理统计缺失，而平均化恰恰在制造这个缺失。
2. **权重 0.15 相对 3h 预算过大**：ep1 就把 PSNR 从 22.61 砸到 20.15（-2.46 dB）。模型在"收敛后的窄吸引盆"里被一个未经调参的大权重拉走，3h 不够它在新目标下重新收敛，结果是"两头不靠"：保真度掉了，纹理也没补上。
3. **方向性证据**：step7 只差 2.59（几乎追平），说明越靠近满速率、学习信号越弱时报废越小；低速率点（step1-3）差 7-9，说明感知损失主要在**破坏已有结构**而不是补充细节。
4. 结论：**想让感知/GAN 类损失真正压 FID，必须 (a) 从头或从很早的阶段就参与训练，而不是在收敛后的模型上事后微调；(b) 配合对抗损失；(c) 用小权重 + 长预算逐步 ramp。** 事后加 3h 特征 L1 是负收益。

### 4.2 工程备注

- 感知损失实现：`perc_loss.py`（VGG16，`torchvision` full build），目标分支 `no_grad`，模块锁 `eval()`；开销约 +7%（27 → 25 img/s），实测无 OOM。
- 该轮训练完成后**编排脚本的自动评估没触发**（我在启动 3 分钟后覆盖了正在执行的 `run_perc_ft.sh`，bash 的读偏移被打断），已手动补跑评估，不影响任何数据。
- `fast_rfid.py` 评估 5000 张图约 4.5 min/次（8 步全部）。

## 4.7 PatchGAN 对抗微调：**也是负结果（rFID 86.50 → 153.02）**

设置：从阶段 1 `ckpt_best`（22.61 dB / rFID 86.50）出发，`L1 + hinge PatchGAN`
（Pix2pix 70×70 感受野、ndf=64、2.77M 参数、随机初始化），
**VQGAN 式自适应权重** `λ = 0.8·‖∂L_rec/∂w‖ / ‖∂L_adv/∂w‖`（w = 解码器末端 `pixel_head` 权重），
G lr 3e-5、D lr 1e-4、10% 步数 ramp、4 卡 DDP、1.5h（1100 步 ≈ 1.16 ep）。

| step | tokens | L1: PSNR / rFID | +PatchGAN: PSNR / rFID | ΔrFID |
|---|---|---|---|---|
| 1 | 32 | 19.04 / 178.07 | 18.76 / 200.69 | +22.6 |
| 2 | 64 | 20.43 / 146.43 | 20.04 / 168.09 | +21.7 |
| 3 | 96 | 21.26 / 126.30 | 20.81 / 146.66 | +20.4 |
| 4 | 128 | 21.80 / 112.26 | 21.30 / 132.44 | +20.2 |
| 5 | 160 | 22.15 / 101.55 | 21.62 / 123.63 | +22.1 |
| 6 | 192 | 22.42 / 93.58 | 21.83 / 119.56 | +26.0 |
| 7 | 224 | 22.58 / 89.31 | 21.90 / 125.94 | **+36.6** |
| 8 | **256** | **22.67 / 86.50** | **21.60 / 153.02** | **+66.5** |

### 4.7.1 三个可读出的现象

1. **8 点全线变差**，满速率 rFID +66.5（+77%），PSNR −1.07 dB。
2. **ΔrFID 在 step1–6 近似恒定（+20±3）**，到 step7/8 突然放大到 +36.6 / +66.5 ⇒ 有**两种不同来源**的损失叠加：
   一种是共享解码器权重被改坏造成的全局面板损失（≈+20），另一种只作用在末步。
3. **PSNR 单调性被破坏**：L1 版本是 22.58 → 22.67（step7→8），GAN 版本是 **21.90 → 21.60**
   （末步比次末步更差）。累计解码"后一步不应比前一步差"，这个反常正好落在**对抗损失的作用位置**上。

### 4.7.2 诊断（按确定性排序）

1. **对抗损失只施加在末步输出上（代码实现选择）——轨迹不自洽。** 末步被要求"讨好判别器"，
   而 step1–7 仍被 L1 约束成 L1 风格；判别器是随机初始化的 PatchGAN，1100 步内就学会
   "平滑=假"，于是生成器最优响应不是"变真实"，而是往末步塞判别器偏好的高频
   （*推断*：依据是现象 3 的单调性反转 + rFID 的额外放大只出现在施加对抗的步）。
2. **判别器过强**：`acc_f`（fake 被判真比例）从 0.75 掉到 0.23、`d_real` 从 0.23 涨到 3.0，
   说明 D lr 1e-4 相对 G 3e-5 领先太多。自适应 λ 只能对齐**梯度范数**（≈0.8×rec），
   无法修正 D 给出的**方向**本身是"高频噪声"这一点。
3. **没有感知/色彩锚**：本轮纯粹 L1 + 对抗，颜色统计无约束。
4. **预算太短**：1100 步对 GAN 是极短（VQGAN 类方法 10k+ 步）。

### 4.7.3 实现与踩坑（可复用）

- `patchgan.py`：`NLayerDiscriminator`（70×70，InstanceNorm）+ `PatchGANTrainer`
  （hinge 损失、D 独立 Adam betas=(0.5,0.9)、**D 不包 DDP**、梯度手动 `allreduce`、监控 `d_real/d_fake/acc_real/acc_fake`）。
- **MUSA 陷阱**：`torch.autograd.grad(loss, 非叶子输出张量)` 报
  `differentiated Tensor appears to not have been used in the graph`。改为对**叶子参数**
  （解码器末端 `pixel_head` 的权重）求梯度比即恢复正常 —— 与 VQGAN 的 `get_last_layer()` 一致。
- **`--gan_weight` 语义**：自适应模式下是**梯度比目标**（不是损失权重）。首版按权重 0.1 用导致对抗项几乎无效，
  必须用 0.8。
- 开销：25 img/s（与纯 L1 相同；自适应 λ 的额外两次"末端权重"反向被 D 的正向开销抵消）≈ 可忽略。

### 4.7.4 若要再试，修正清单（按重要性）

1. 对抗损失施加到**全部 8 步**（或每优化步随机抽一步），保证轨迹自洽；
2. **削弱 D**：lr 1e-4 → 2e-5、加谱归一化、或每 2 步才更新 D；
3. 加**感知/色彩锚**（PW 0.02–0.05）防止颜色漂移；
4. 预算 ≥3–4h（10k+ 步），并**每 30 分钟测一次 rFID** 判断趋势而不是等终局。

结论：**在"已收敛的确定性回归模型上事后加 1.5h PatchGAN"是负收益**（+77% rFID）。
这不否定对抗路线的潜力，但证明了"短预算 + 末步单点对抗 + 强 D"的组合必然把模型推向 FID 更差的方向。

## 5. 结论与差距归因

### 5.1 最终数字

| 速率点 | 用量 | 我们 (L1, 14ep) | ALIT-S | ALIT-B | 差距 |
|---|---|---|---|---|---|
| 32 token | 384 values | PSNR 19.04 / **rFID 178.07** | 22.57 | 22.15 | 7.9× |
| 128 token | 1536 values | 21.80 / **112.26** | 11.69 | 10.44 | 9.6× |
| 256 token | 3072 values | **22.67 / 86.50** | **8.25** | 8.19 | **10.5×** |

**结论：24h 内在 256²、3072 values/图、8 步循环解码（架构未改）下，rFID 最好做到 86.50，未超过 ALIT 的 8.25，差 10.5×。** 三种"sota 技巧"都没能改善：感知损失（3h，w=0.15）让 rFID +9.0（负），PatchGAN 对抗微调（1.5h）让 rFID +66.5（负），rFID-loss 辅助损失因训练器 bug 未跑成（§3）。

### 5.2 这 10 倍差距从哪来（按贡献排序）

1. **没有对抗训练 / 没有 codebook —— 结构性差距，占大头。**
   ALIT 是 VQGAN 路线：VQ 码本 + 感知损失 + **对抗损失**。FID 度量的是生成分布与真实分布的**二阶统计（Inception 特征协方差）差异**，对抗损失是唯一直接优化"看起来像真图"的机制。我们是确定性回归（L1），输出天然是条件均值 ⇒ 纹理被平均掉。本实验的负结果（§4）恰好证明：**不用对抗信号，仅靠特征 L1 换不来 FID**。
2. **训练预算差 20-30 倍。** 我们 14 ep（13.7h）vs ALIT ≥400 ep。§4.5 的曲线显示 rFID 在 ep14 仍以 ~2.2/epoch 下降，**这条线当前最便宜的收益就是加轮数**（ep30 预计 62-65）。
3. **8 步循环读出在高速率端饱和。** step6→7→8 的 PSNR 增益只有 +0.16/+0.09 dB，rFID 增益 -4.3/-2.8；而 step1→2 是 +1.39 dB / -31.6。说明累计窗口越往后，新 token 带来的增量越小 —— 这与之前 448²（瓶颈 192→448）的结论一致：**8 步短板的本质是高速率端的循环读出 rate-scaling，而不是瓶颈宽度或分辨率**。
4. **模型容量不是瓶颈。** 480.6M 参数量是 ALIT-S（173M）的 2.8 倍，但 rFID 差 10 倍 ⇒ 加大模型/加宽瓶颈（此前 192→448 只换来全曲线 +1 dB）不是杠杆。

### 5.3 要真正逼近 ALIT 需要什么（下一步建议，按性价比排序）

1. **加对抗损失**，但必须按 §4.7.4 修正：对抗施加到**全部 8 步**、削弱 D（lr 2e-5 + 谱归一）、加感知/色彩锚、预算 ≥3–4h 且中途每 30 分钟测 rFID。首轮 1.5h 末步单点对抗的失败（rFID +77%）正是没做这些修正的结果；若按修正版仍无效，才可判定对抗路线在本架构上不成立。
2. **把训练从 14 ep 拉到 60-100 ep**（当前最便宜，预计到 60-70）。
3. 感知损失**权重降到 0.02-0.05 并从早期参与**（本实验证明事后大权重微调是负收益）。
4. 若要复现 ALIT 的 8.25，还需 codebook（VQ）或至少更强的熵模型；纯确定性回归 + 循环读出在 3072 values/图这个速率点上，rFID 是有硬下界的。

### 5.4 诚实的元结论

用户要求"24h 内从 0 训练、看能不能超过 ALIT 的 rFID"。**没做到，差 10.5 倍**，而且这个差距不是调参能弥补的：它来自**训练目标（回归 vs 对抗生成）与训练预算（14 vs 400 ep）的量级差**。另外还试了 PatchGAN 对抗微调（1.5h）：rFID 从 86.50 涨到 153.02，并暴露了"末步单点对抗破坏累计解码单调性"（step8 PSNR 反而低于 step7）这个可复现的结构性现象 —— 对抗损失的作用位置必须与整条逐步轨迹一致。

本实验也给出了三条有正面价值的结论：(a) 把分辨率和速率口径对齐后，我们的 rFID 从 448² 时代的 ~102 降到 86.5；(b) rFID 在 14 ep 仍未收敛，加轮数有明确收益；(c) 事后加 VGG 特征 L1 是负收益，必须配对抗信号。

## 6. 下一步计划（见 `doc/2026-11-22/PLAN_refiner_roadmap.md`）

本报告的三次"技巧"尝试（感知损失 / rFID-loss / PatchGAN）均为负结果或未完成，差距归因清楚后，下一阶段路线定为
**解码端 refiner（post-filter）**：冻结主干、用 6–10M 参数的小 refiner + hinge PatchGAN + VGG 感知（对抗作用在 refiner 输出，
不再触碰主解码器），一个 refiner 服务全部 8 个速率点。计划含 P0（FID 分解 + 预训练后处理天花板实验，1–2h 无训练）、
P1（refiner 训练，4–6h）、P2（主干长训练）、P3（补 LPIPS/DISTS 与 RDP 三联图）、P4（消融与写作），
以及 MUSA 踩坑清单与资产路径。
