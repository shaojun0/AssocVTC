# DanQing100M 抽样训练的可行性评估

**日期**：2026-11-06 · **背景**：run2 续训中（明早 06:00 完成），若消融好则考虑"更大范围的数据"；用户提出候选 `DanQing100M`。
**结论：不建议作为主训练数据抽样；只适合当"通用中文 replay"的小比例补充，且必须先接受 52% 死链 + CC-BY-NC 许可 + 任务模板重造三项成本。**

## 1. 它是什么（一手核实，非二手转述）

- 论文：*DanQing: An Up-to-Date Large-Scale Chinese Vision-Language Pre-training Dataset*（arXiv 2601.10305，DeepGlint/Glint Lab，2026-01）
- 定位：**CLIP/SigLIP2 式图文对比预训练数据**，9,989 万条 2024–2025 年网页图文对，从 10.5 亿原始对过滤而来（过滤掉 90.46%）
- 字段：`url` + `alt_text`（网页 alt）+ `recaption`（GLM-4.1-base-9B 生成的短描述）
- 分发：HF 只给 **URL 表**（67 个 parquet，实为 ~20GB 文本）；图像本体 12TB 在 ModelScope（我这边接口返回「无权访问该数据集」，需授权/登录）
- 许可：**CC-BY-NC-4.0（非商用）**

## 2. 实测（在主机器抽 1 个分片 train-00000，150 万行 + 爬 40 个 URL 看图）

| 项 | 实测值 |
|---|---|
| 分片行数 / 下载 | 1,500,000 行 / 296MB / 12s（hf-mirror 24MB/s） |
| alt_text 长度 | mean 21.7 字（中文 16.2 字），p90 38 |
| recaption 长度 | mean 41.8 字（中文 35.8 字），p90 64 |
| URL 域名 | 24.3 万独立 host；最大 `cbu01.alicdn.com`(淘宝/1688 商品图) 2.8%、百度图床 3 组各 0.8%、udn/搜狐/网易新闻、wp 博客 |
| **图片下载成功率** | **19/40 ≈ 48%**（403 热链、ConnectionError、非图片、SSL 失败） |
| 成功图尺寸 | min-edge 全部 >100（符合论文过滤）；中位 93KB（原图，256px 压缩后 ~25KB） |
| 内容抽样（16 张，见 `danqing_sample_montage.jpg`） | 五金件产品图、台币钞票、足球赛（带中文说明字幕）、结婚照、金条、**论坛 emoji 截图**、路牌、工厂厂房、酒店外景、菜品/糖果…… |

判读：
1. **电商商品图 + 新闻图 + 博客图为主体**，混入不少截图/带文字水印/带文字覆盖层的图（论文用 CLIP 距离洗过"OCR 主导图"，仍有残留）。
2. 领域与"核电隐患/工业安全场景"差距极大——没有裂纹/腐蚀/泄漏/异物/违章这类关键语义。
3. 描述是**整图自由描述**，没有类目体系、没有标签；要做分类必须自己聚簇/映射，等于另造一个任务。
4. 48% 成功率是抽样训练的隐形税：拿 N 张要好 2 倍以上 URL 抓取量。

## 3. 为什么不适合当"更大范围数据"的主体

1. **任务形态不匹配**：vlm8b 当前是"100 候选列表 → 输出类名"的 answer-only CE（`ans_pos` 平移 8 预算）；DanQing 是 CLIP 图文对。要接进来必须新造模板（整图描述 / 选最匹配描述），是新增任务，不是"换个数据源"。
2. **粒度不匹配**：8 个视觉 token 要生成 20–40 字中文描述，信息瓶颈下几乎不可能收敛；硬加会让 loss 长期高位并稀释主任务（每个 batch 8 个预算行）。
3. **与主线任务领域错位**：最终目标是核电隐患图像的字幕生成/隐患识别，DanQing 提供不了领域信号。
4. **许可**：NC-4.0 不能商用；"可复用中间件/试点/标准"若有商用属性则不合规，纯论文可以。

## 4. 可选方向（按性价比排序）

| 方向 | 做法 | 代价 | 适配结论 |
|---|---|---|---|
| **A（推荐）** | ImageNet-100 → ImageNet-1K / 更多类目 | 同任务同格式，仅候选列表 100→1000，标签现成 | 直接检验"数据/类目扩容后 8 预算机制是否被激活" |
| **B（推荐）** | 换到真正吃细节的中文任务：图片字幕 / OCR（COCO-CN、TextCaps、中文文档 OCR） | 需造模板，但 8 token 差异能被测出来 | 与"语义压缩+字幕生成"主线一致 |
| C | DanQing 抽 1–2 万张，只做 caption，占 batch 5–10%，当 anti-forgetting 正则 | 需 img2dataset 爬图（~2 倍 URL），许可受限，8 token 下收益存疑 | 只能当辅助，先 5k 张验证质量 |
| D | 纯文本 replay（掺通用 QA/算术题）+ 降 lr / LoRA | 最便宜，不需爬图 | 治"通用能力遗忘"（75%→1.7%）最省事 |

## 5. 若走 C：抽样流水线（预估）

- 下载 1–2 个 parquet 分片（~600MB）→ 抽 5 万条 URL → img2dataset（256px, keep_ratio, 32 线程）
- 预期产出 ~2.4 万张、~0.7GB、耗时 ~1h、下行 ~15GB
- 落成 `{image, messages}` 中文描述 jsonl，与主数据按 9:1 混采
- 前置：主机器磁盘只剩 25G 且 run2 在跑（到明早 06:00），建议跑完再做；region-9（24410）当前 SSH 连接被拒（实例疑似关机/释放），需用户确认

## 6. 一句话

**DanQing 是"给 CLIP 做预训练"的通用中文图文对，不是"给 4B VLM 做指令微调"的数据；抽它来训练，收益在"抗遗忘"，不在"提升主指标"，且要付 48% 死链、NC 许可、新造任务模板三项税。真正的"更大范围"应走 ImageNet-1K 或换吃细节的中文任务。**
