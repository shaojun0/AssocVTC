> 指标（都定义成"CE 降低 = 正数更好"）：`vision_gain = CE(视觉置零) − CE(正常)`；`spec_gain = CE(错图) − CE(正常)`；`mean_cost = CE(8 token 取均值) − CE(正常)`（≈0 ⇒ token 冗余）；`repeat_cost = CE(8 份第 1 token) − CE(正常)`；`budget_gain = CE(k1) − CE(k8)`。

七条结论：

1. **k 曲线在每个源上都饱和在 k=1。** 20 个 (source, 图/文) 组合的 CE(k) 从 k1 到 k8 变化全部 ≤0.02，多数 ≤0.005。
2. **预算是条件性有效，不是有害。** `budget_gain` 与 `vision_gain` 在行级强正相关：heldout rho=+0.40、in100 rho=+0.43，**每个源内部**也都是 +0.3~+0.6（唯一例外 slake +0.07，因为它 1 个 token 就够了）。
3. **"图有用"的行上预算真的有用：** in100 val 中 `vision>0.4` 的 46% 行，acc **51.1%→62.0%（+10.9pp）**；混评 `vision>0.3` 的 78 行 **16.7%→20.5%（+3.8pp）**；in100 训练行 +20pp。**"图误导"的行上预算有害：** heldout `vision<−0.1` 的 262 行 budget −0.038、acc 1.5%→0.8%；in100 val `vision<−0.05` 的 75 行 budget −0.183。
4. **所以平均≈0 是"两类行互相抵消"的结构性结果**，不是机制坏了：混评图像行里真正"图有用"（vision>0.1）只占 14.6%，"图误导"占 14.5%，其余 71% 是"图可有可无"（多为能被文本/记忆解决的题）。
5. **训练集与测试集同构，但训练集信号更强：** train 图像行 budget +0.012（+1.9pp），主要来自 ImageNet-100（+0.120/+20pp）和"图有用"的硬行；文本行精确为 0（blank 图像 + 已背到 CE 0.041）。
6. **冗余是任务决定的，不是投影头塌缩：** 混评图像行 `mean_cost≈−0.005`、`repeat_cost≈−0.002`（8 个 token 换成均值/第 1 个复制，CE 不变）；但 in100 是 `+0.100/+0.002`、in100 训练行 `+0.311/+0.130`（token 各含不同信息）。同一个投影头，在"需要 100 类判别"时 token 有分工，在"读图表/OCR"时没有。
7. **根本瓶颈是编码器侧容量：8 个 visual token = 32 个 z token（4 拼 1）**，k∈1..8 只是把**同一份 32-token 信息**换个摆法，不可能增加信息。粗粒度语义任务（slake/in100/mmstar）1 个 token 就够 ⇒ k 平；细粒度任务（OCR/图表/文档/数学图）所需细节**根本不在**这 32 个 token 里 ⇒ k 平且 acc 极低（chartqa 1.7%、docvqa 1.7%、textvqa 10.8%、ocrbench 5.8%）。

## 1. 先把尺子校准：评测协议的 acc 一直被低估（重要修正）

`eval.py` 原来的 greedy 生成把**整段文本（含答案）**喂给 `generate`，模型看到答案后继续生成，大量输出空串。修正为**只喂到 answer 之前**（`--gen-protocol prompt`，现为默认）后，同样 300 行（seed 42）：

| 模式 | 旧协议 acc k1→k8 | **修正后 acc k1→k8** | 修正后 CE k1→k8 |
|---|---|---|---|
| normal | 22.7%→22.3% | **48.7%→49.3%** | 0.584→0.585 |
| null（视觉置零） | 28.0%→28.0% | **48.3%→48.3%** | 0.604→0.604 |
| shuffle（错图） | 23.3%→21.7% | **48.7%→48.7%** | 0.619→0.619 |

- ImageNet-100 val（250 行）：旧 14.8%→22.8% ⇒ **修正后 29.2%→32.4%**。
- **run3 报告里"null > normal（视觉有害）"是协议伪影，必须撤回**：修正后 normal 略好于 null（acc +1.0pp、CE −0.019），错图再差一点（CE +0.034）。
- 趋势结论不受影响：修正后 k 曲线依旧平；但**所有绝对 acc 数字都要用新协议重报**（run1/run2 的 checkpoint 已删，无法重跑，历史对比只能标注"旧协议口径"）。

## 2. 方法

- `eval_dump_per_sample.py`：逐行落盘 8 档 CE × 5 种视觉消融 + k∈{1,8} greedy + 视觉 token 诊断；抽样按 `(source, task, 图/文)` 分层（**每源等量**，便于比较；与 heldout 真实配比不同）。
  - `normal / null / shuffle / mean（8 token 均值广播）/ repeat（第 1 个 token 复制 8 份）`
- 规模：heldout 2,400 行（15 个图像组合 ×120 + 5 个文本源 ×120）；train 1,300 行（26 组 ×50，另有 ×120 的复核任务在跑）；in100 val 400 行随机。
- `vis_probe.py`：`within/across cos`、跨图参与率（有效维数）、full-attention 层"文本 query→视觉位置"注意力份额。
- 全部在 GPU0/GPU1 并行跑，产物落在 `/root/vlm8b/logs/screen_*.jsonl`。

## 6. 机制分析：为什么 k 曲线是平的

### 6.1 行级相关：预算收益 = 视觉收益的子集

- heldout 全体 rho(budget, vision)=+0.395（p=1e−90）；in100 +0.434；train +0.4~+0.6。
- **源内**也全部为正（heldout 图像行：ai2d +0.45、chartqa +0.44、countbench +0.51、mathvision +0.51、mmmu +0.52、mmstar +0.59、scienceqa +0.53、realworldqa +0.49、textvqa +0.33、we_math +0.35；slake +0.07）。train 同理（mmstar +0.61、textvqa_train +0.63、scienceqa +0.62、realworldqa +0.54）。
- ⇒ **不存在"某些行图没用但多给 token 也有用"的方向**；k 的全部作用都被"这一行的图是否被用上"解释。

### 6.2 token 冗余度（5 种消融）

- 混评图像行：`mean_cost −0.005`、`repeat_cost −0.002`（换成 8 个均值 token 或 8 份第 1 token，CE 几乎不变）⇒ **8 个 token 在 LM 眼里近乎可互换**。
- in100：`mean_cost +0.100`（val）/ `+0.311`（train），`repeat_cost +0.002/+0.130` ⇒ **token 各含不同信息，尤其训练行**。
- 结论：投影头没有塌缩（in100 证明它有产出差异 token 的能力），是**混评任务只需要 token 里的"公共粗语义"**，8 个 token 的差异部分对答案无用甚至有害。

### 6.3 注意力：LM 本来就"半看半不看"视觉 token

`vis_probe.py`，full-attention 8 层、16 头，文本 query 对视觉位置的注意力份额（vs 均匀分布 k/L）：

| 行类型 | 均匀份额 | 实际份额 | 比值 |
|---|---:|---:|---:|
| 图像行（12 源，n≈16） | 9.8% | 5.6% | **0.53×** |
| 文本行（4 源，n=4） | 6.0% | 4.2% | 0.70× |
| docvqa | 11.9% | 10.4% | **0.88×**（最高，与 vision_gain +0.077 一致） |
| chartqa | 11.2% | 3.8% | 0.34×（最低） |
| mmstar | 5.1% | 2.0% | 0.38× |

⇒ 视觉 token 拿到的注意力**低于按位置数量应得的水平**（0.53×），只有 docvqa 接近 1；说明模型整体倾向"少看视觉、多看文本"，与"文本行占 2/3 训练"高度一致。

### 6.4 表征离散度：图与图之间可分，但"有用维度"只有 3–21

`vis_probe.py`（每源 60 张）：

- 文本行（blank 图）：跨图 cos=1.000、参与率 0 ⇒ 8 个 token 对所有文本行完全相同（一个常量前缀）。
- 图像行：跨图 cos 0.38–0.78，去均值后 ≈ −0.01（图间差异是"小残差"，不是没差异）；跨图参与率 pr_vis 3.1（slake）～20.6（textvqa）。
- **pr_vis 与 vision_gain 无关**（rho −0.31，p=0.28）：textvqa 表征最"分散"却毫无收益 —— **信息在表征里，但 LM/任务用不上**（OCR 需要的是细粒度定位，不是"分散度"）。
- 对照：`within`（同图 8 token 两两 cos）0.20–0.76；混评里 `within` 越高的源、budget 越负（rho −0.60，p=0.02）——token 越雷同，多给越没用。

### 6.5 容量论证（结论的根）

- 视觉通路：`z_s (32×1744) → 逐 token 投影 640 → 4 个拼 1 → vis (8×2560)`。
- **k∈1..8 只决定"暴露多少 z token"，不改变 z_s 的信息量上限（32 个 token）。**
- 因此：
  - 粗语义任务（slake 71.7%、scienceqa 74.2%、mmstar 51.7%）：1 个 token（4 个 z token）已够 ⇒ k 平；
  - 需要"多类判别"的任务（in100）：32 个 token 里的差异是有用的 ⇒ 8 个全给最好（"图有用"行 +11pp）；
  - 需要**细粒度文字/坐标/细节**的任务（chartqa/docvqa/textvqa/ocrbench/mathvision）：32 个 token 根本装不下 ⇒ k 平且 acc 1%–11%，再多 epoch/数据也只是记忆。
- **要提升的是编码器侧的分辨率/粒度（更多、更局部、更高分辨率的 token），不是 LM 侧的 k。**

## 7. 经验 & run4 建议

### 7.1 七条经验

1. **预算机制的"验收指标"应该是分源的 `budget_gain`，不是总体平均。** 总体会被两类行抵消；建议固定报：`vision>0.1 行的 acc/CE 增益`、`vision<−0.1 行的损失`、`mean_cost`。
2. **数据配比的核心量是"图有用率"**（vision>0.1 的行占比），而不是"图像行占比"。run3 混评：文本 67%、图像 33%，而图像行里约一半是"图摆设"（|vision|<0.02）⇒ 真正教视觉通路的样本约 8%。
3. **OCR/图表/文档/数学图是"结构性不可学"**：8 个粗 token 装不下细节，训练集 CE 0.2–0.5 / acc 48%–78% → heldout 1%–11%。若不动编码器，这些数据只能起到"占位+干扰"作用，应降权或换任务形态（改成"图→一句粗描述"）。
4. **文本行对视觉训练贡献精确为 0**（train CE 0.041、vision/budget 都 0），却占了 67% 的梯度步数。要么降到 30%–40%，要么重训时给文本行**零视觉 token**（当前 blank 图反而制造了一个常量前缀，属额外分布偏移）。
5. **ImageNet-100 是唯一"预算有效"的锚点**：3k 行时 heldout 34.5%、"图有用"行 +10.9pp；run2 的 66k 行时 CE 增益 +0.03。**要保住预算机制的可信度，锚定应回到 10k–20k 行。**
6. **"图误导"行（vision<−0.1）值得单独治理**：混评 14.5%、in100 val 19%（且 acc 全 0）——多为模型读错图/图质量差/选择题干扰图。它们让预算变成负收益，建议在训练/评测里打标签并单独统计。
7. **评测口径必须统一**：修正 greedy 协议（只喂 prompt）；每源 ≥100 行（当前 25 行/源 ≈ 4pp 抖动）；并且**不要用 300 行随机样本替代分源评测**。

### 7.2 run4 数据配方建议（在现有 122k 行框架内，按"图有用率/容量"重排）

| 桶 | 现状 | 建议 | 理由 |
|---|---|---|---|
| 文本行（mmlu/cmmlu/mmlu_pro/mmlu_redux/ceval） | 69k（56%） | **30k–40k** | vision/budget 恒为 0；只需维持文本能力，避免灾难遗忘 |
| gsm8k/math（文本数学） | 13k | 13k | 文本推理同样 0 增益，但保住数学能力 |
| ImageNet-100 | 3k | **12k–20k** | 唯一预算有效锚点；图有用率 100% |
| slake / countbench / realworldqa | 5.8k | 6k–8k | 粗语义图任务，泛化尚可（slake 71.7%） |
| docvqa(+train) / textvqa(+train) / chartqa(+train) / ocrbench | 18k | **降权到 8k–10k，或改任务形态** | 记忆不泛化（heldout 1%–11%）；不改编码器时加数据收益极低 |
| ai2d/scienceqa/mmmu/mmstar | 9.6k | **降到 3k–4k** | 图摆设（vision≈0）、训练 acc 82%–100%，heldout 主要靠文本+记忆 |
| 若要"预算真的有用" | — | 需要**编码器侧改动**：z token 从 32 提到 128–256（或 patch 级 token、448→更高分辨率），让 8 个预算 token 承载更多细节 | 容量论证（§6.5）：k 不增加信息，只有 z_s 能 |

### 7.3 若要立刻验证"预算机制能成立"的最小实验

1. **in100 锚定回到 20k**（不改结构）：预期 heldout in100 CE k1→k8 从 0.474/0.475 变回 ~0.40→0.37、acc +6~8pp，"图有用"行 +12pp 以上。
2. **文本行零视觉 token** 重训：预期文本行 CE 不变或略好（消掉 blank 常量前缀），视觉行不变。
3. **in100 val 上做 k=1,2,4,8 的 token 裁剪**：确认 k=4 是否已接近 k=8（in100 训练行 mean_cost +0.311 说明 token 有分工，应在 k=4 看到拐点）。
