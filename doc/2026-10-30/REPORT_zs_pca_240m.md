# 240M 基线（降维训练之前）输出 token 的按位置 PCA 冗余分析（2026-10-30）

**一句话**：对 240M 模型（K=32，每 token 1248 维，**未做 448/224 维瓶颈微调之前**）在 IN-100 val 5000 张上输出的 `z_s`，按 32 个 token 位置**逐位置做 centPCA**：前 448/224 个主成分保留方差中位数 **98.57% / 88.51%**、`rank@95%` 中位数 **335/1248（26.8% 宽度）**、participation ratio 中位数 **27.5** ⇒ **「token 主成分冗余」在数据侧成立**；但谱是重尾（95%/99% 仍要 335/474 维），且**零训练 PCA 截断（r=448 掉 0.47 dB、r=224 掉 2.81 dB）比训练出的 448/224 维瓶颈臂（掉 0.25/1.85 dB）更差** ⇒ **方差保留率不等于重建保真**，「能降维」不完全等价于「PCA 主成分可以直接砍」。另：32 个位置极度异质（7 个位置近常量、只占 1.4% 内容方差），跨位置能量上也高度集中（同图 32 token 的 `rank@95 ≈ 19–20/32`），这是**第二种（token 数）冗余**，支撑后续减 token 实验。

> 用户口径原文：「能降维说明原始 token 本身的 PCA 主成分很可能是冗余的 ⇒ 对降维训练之前的模型输出的 token 按位置对测试集做 PCA，同时保留模型输出的 token 向量，以便后续做进一步实验。」
> 本报告 = T1 提取 token + T2 逐位置 PCA + T3 零训练 PCA 截断解码对照。**降维实验**指 2026-10-26 的 zs448/zs224 臂（编码器末端 FC 1248→448/224，全量微调 3 ep；见 [`REPORT_rfid_m240_pca.md`](../2026-10-26/REPORT_rfid_m240_pca.md) §11/§12）。

## 0. 结论速览（先读这一节）

| # | 结论 | 关键数字 |
|---|---|---|
| 1 | **数据侧冗余成立** | 逐位置 centPCA 前 **224/448** 维累计方差中位数 **0.8851 / 0.9857**；`rank@95%` 中位数 **335**（= 1248 的 26.8%）；参与率 PR 中位数 **27.5**（2.2% 宽度） |
| 2 | **但谱是重尾，不是「少数主成分包打天下」** | `rank@90/95/99/99.9` 中位数 = **245 / 335 / 474 / 661**；448→1248 的 800 个方向合计只承载 **1.4%** 方差，但丢掉它们在解码器上要付 0.25 dB（见结论 4） |
| 3 | **位置间极度异质** | 7/32 位置近常量（位置常量占其能量 **96.8–99.3%**），合计只占总内容方差 **1.4%**；12 个高方差 + 10 个中方差位置合计占 **95.0%**；总内容方差跨度 **72×**（8.8–638.2） |
| 4 | **方差保留率 ≠ 重建保真（关键反例）** | 同 200 张子集配对：**训练臂 zs448 = 27.943 dB（−0.242）** vs 零训练 oracle PCA 截断 **r448 = 27.713（−0.472）** ⇒ 训练臂好 **+0.230 dB**；**训练臂 zs224 = 26.281（−1.904）** vs **r224 = 25.372（−2.814）** ⇒ 训练臂好 **+0.909 dB**（全量 5000：训练臂只掉 0.25/1.85 dB）⇒ 训练出的 448/224 维子空间比「最大方差子空间」更任务相关 |
| 5 | **跨位置（token 数）也有冗余，但 token 不是副本** | 同图 32 token：pairwise cos 均值 **0.157**、frac(cos>0.9) **1.0%**、E-A5 熵指数口径 **0.762×K**；但能量参与率 **6.60**、`rank@95 ≈ 20/32`（去位置均值后 11.82 / 19/32）⇒ 能量集中在少数共享方向 |
| 6 | **降维臂的共享映射上界** | 一个共享线性映射（池化、逐位置中心化）的数据侧 oracle 上界：前 **448 = 92.87%**、前 **224 = 77.27%** 方差；逐位置独立基是 **98.57% / 88.51%** ⇒ 「共享基 vs 逐位置基」相差 5.3 / 10.2 pp |

**给论文/后续实验的三句话**：
1. 240M/K=32 的 `z_s` 在**每 token 维度**上高度冗余：占宽度 35.9% 的 448 维即可在数据侧 oracle 保留 98.57% 方差（共享线性映射口径 92.87%），这与 zs448 臂只掉 0.25 dB 一致。
2. 但**按方差截断不是最优的降维方式**：零训练 per-position PCA 截断到 448 维就掉 0.47 dB（> 训练臂 0.25 dB）⇒ FC 瓶颈的价值不只是「砍掉小方差方向」，而是学到了对重建更重要的方向（warm start 用的是 `decoder.mem_proj` 权重的 SVD，不是数据 PCA）。
3. **位置层面的冗余更值得挖**：7 个 token 位置几乎不携带内容（近常量），同图 32 token 的有效能量秩只有 ~6.6–11.8 —— 下一步的压缩应优先考虑**减 token 数 / 位置剪枝**，而不是继续压每 token 宽度。

**读法**：
- **宽度冗余确凿**：`rank@95%` 的中位数只有 **335/1248 = 26.8%**；也就是说「达到 95% 方差」平均只需要 27% 的 token 宽度。
- **但不是「几个主成分就够」**：`rank@99%` 中位数 474、`rank@99.9%` 661；从 448 维加到 1248 维（+178%）只多买到 **1.4%** 方差，可这 1.4% 分布在 ~800 个方向上（重尾谱）。
- `PR=27.5` 与 `entropy rank=125.1` 的差异来自口径：PR 对少量大方差方向极敏感（能量集中），熵指数更平滑；两者都远小于 1248，方向一致。
- **不居中口径（对照，仅作诊断）**：若不去位置均值，首主成分就占 0.6758 能量（≈ 位置常量方向），`rank@95` 中位数降到 185.5、前 448 = 0.9964 —— 这是「位置常量」造成的**虚假冗余**；回答用户问题必须用 centered 口径（本报告主口径）。

## 3. 主结果 B：与降维实验（zs448 / zs224）的对照

### 3.1 值数 vs 数据侧方差保留（oracle 上界）

| 码 | 每图连续值 | 数据侧方差保留（逐位置基） | 共享线性映射上界 | 训练臂实测 PSNR（5000 张） |
|---|---|---|---|---|
| base（1248 维/token） | **39,936** | 1.0 | 1.0 | **27.936** |
| 448 维/token | **14,336** | **0.9857**（median；mean 0.9842） | **0.9287** | **27.688**（−0.248 dB） |
| 224 维/token | **7,168** | **0.8851**（median；mean 0.8987） | **0.7727** | **26.083**（−1.853 dB） |

- 「逐位置基」= 每个位置一套自己的 448/224 维子空间（**这不是 FC 能做到的**，是数据侧 oracle 上界）。
- 「共享线性映射」= 一个共享 PCA 基（池化、逐位置中心化后）= **单个 Linear(1248→448/224) 的数据侧最优方差上界**；它比逐位置基低 5.3 / 10.2 pp，因为 32 个位置只部分共享子空间（见 §4）。
- 训练臂是**共享映射 + 全量微调**，其数据侧参照应是「共享基上界」（448 维 **92.9%**、224 维 **77.3%** 方差）；逐位置 98.6%/88.5% 只是「每位置一套基」的 oracle，**不是 FC 能达到的**。
- ⚠️ 方差保留率本身不能预测掉点：真实答案是 §3.2——训练臂比「oracle 最大方差截断」更好。

### 3.2 零训练 PCA 截断 vs 训练臂（同 200 张子集，配对）

口径：val 等间距子集 `idx=arange(0,5000,25)`（200 张、100 类每类 2 张）；PCA 基用**全部 5000 张**拟合（含评测子集 ⇒ transductive **oracle 上界**）；截断=投影到前 r 个主成分再反投影回 1248 维；解码器参数不变、16 步末步；CPU fp32。

| 臂 | 每图值数 | PSNR / dB | L1_norm | SSIM | ΔPSNR（vs base 同子集） |
|---|---|---|---|---|---|
| base（`model(x)` 末步） | 39,936 | **28.1856** | 0.11924 | 0.8382 | — |
| T1 token → 解码器（raw，交叉验证） | 39,936 | **28.1856** | 0.11924 | 0.8382 | **+0.0000** |
| PCA 截断 r=1248（恒等对照） | 39,936 | **28.1856** | 0.11924 | 0.8382 | **+0.0000**（Δ=7.6e-8） |
| **训练臂 zs448** | 14,336 | **27.9432** | 0.12355 | 0.8269 | **−0.2424** |
| PCA 截断 r=448（零训练，oracle 基） | 14,336 | 27.7134 | 0.12643 | 0.8241 | −0.4722 |
| **训练臂 zs224** | 7,168 | **26.2812** | 0.14883 | 0.7639 | **−1.9044** |
| PCA 截断 r=224（零训练，oracle 基） | 7,168 | 25.3719 | 0.16685 | 0.7395 | −2.8137 |

**配对结论（同一 200 张、同脚本同口径）**：
- **448 维**：训练臂 **27.9432** > 零训练 oracle PCA 截断 27.7134，**训练臂好 +0.230 dB**；
- **224 维**：训练臂 **26.2812** > 零训练 oracle PCA 截断 25.3719，**训练臂好 +0.909 dB**；
- 与全量 5000 口径自洽：zs448 −0.248（全量）vs −0.242（子集）、zs224 −1.853 vs −1.904；子集 base 比全量高 +0.25 dB（子集偏易）⇒ **子集结论可外推到全量口径**。
- 管线交叉验证：`model(x)` vs T1 token 直接 decode 的 ΔPSNR = **1.5e-8 dB**（max|Δ|=5e-7），r=1248 恒等 ΔPSNR = 7.6e-8 ⇒ 提取/解码/指标三环自洽。

**解读**：
- **方差保留率高 ≠ 掉点少**：r448 在数据侧保留 98.57% 方差，零训练截断却掉 0.47 dB；说明丢掉的那 1.4% 方差**不是噪声**，而是解码器敏感的高频/细节方向。
- **降维臂的优势不能由「token 子空间线性可压缩性」解释**：即便 PCA 基在**全 5000（含评测图）**上拟合（transductive/oracle 上界），零训练「PCA 截断 + 基线解码器」仍比训练臂**多掉 0.23 / 0.91 dB**。训练臂的增益来自 **decoder 协同适配**（warm start 对 `decoder.mem_proj.weight` 做 SVD 秩近似 + 3 ep 全量微调）——数据 PCA **既不是它的替代，也不是它的上界**。
- 一句话：**「主成分冗余」是数据的性质，「能降到 448 维」是训练出来的性质**；两者方向一致（1248 维确实有大量可压空间），但不能互相推导。

## 4. 跨位置结构：第二种冗余（token 数）

| 指标 | 值 |
|---|---|
| 位置均值范数 | 24.57–35.07（token 总范数几乎恒定 35.12–35.44） |

| top-224 子空间主角度 | 平均角 49.68°；重叠 0.448（随机 ≈0.180，2.5×）⇒ 有部分共享，但**没有单一共享子空间** |
| 同图 32 token（原样） | pairwise cos mean **0.157**、frac(cos>0.9) **1.0%**；能量 PR **6.60**；`rank@95 = 20/32`、`rank@99 = 27/32`；top1 能量占比 0.289 |
| 同图 32 token（去位置均值） | PR **11.82**；`rank@95 = 19/32`、`rank@99 = 23/32` |

| z_cls | `rank@95`=429、`cum@224/448` = 0.8291/0.9572、PR 48.1（与 z_s 单位置同量级） |

**两种口径不矛盾**：token **不是彼此的副本**（两两 cos 0.157、frac>0.9 仅 1%、E-A5 口径 0.76×K），但**能量上**由少数共享方向主导（PR 6.6、去位置均值 11.8，`rank@95` 只需 ~20/32）⇒ 32 个 token 里有一部分「token 数冗余」：
- 7 个近常量位置几乎不携带内容（占 1.4% 内容方差）；
- 其余位置的 token 也共享一个低维「图像级」方向（top1 能量占 28.9%）。

⇒ **后续更划算的压缩方向可能是减 token 数 / 位置剪枝**（与 2026-10-19/21 的 K-sweep 结论互补：K 减少的代价主要来自 A 相优化，而不是「信息真不够」）。

---

## 5. 结论（可直接写进论文/实验记录的句子）

1. **240M/K=32 的 `z_s` 在每 token 维度上高度冗余**：逐位置 centPCA 下，占宽度 35.9% 的 448 维在数据侧 oracle 保留 **98.57%** 方差（共享线性映射口径 **92.87%**），224 维对应 **88.51% / 77.27%**；`rank@95%` 中位数仅 **335/1248**。这与 zs448 臂只掉 0.25 dB 一致。
2. **但「主成分冗余」≠「少数主成分就够」**：谱是重尾，95%/99% 仍要 335/474 维；448→1248 的 800 个方向只占 1.4% 方差，却支撑 0.25 dB 的画质。
3. **方差保留率不是重建保真的充分统计量**：同 200 张配对，训练臂 zs448/zs224 掉 **0.242 / 1.904 dB**，而零训练 oracle per-position PCA 截断 r448/r224 掉 **0.472 / 2.814 dB** ⇒ 训练臂分别好 **+0.230 / +0.909 dB**；即便 PCA 基在测试集上拟合（oracle 上界）。**降维臂的价值在 decoder 协同适配，不在「线性可压缩性」**。
4. **位置层面冗余更大**：7/32 位置近常量（合计 1.4% 内容方差），同图 32 token 能量 `rank@95 ≈ 19–20/32`；下一步优先考虑减 token 数。
5. **数据已保留**：`z_s`/`z_cls` 全量 5000 张（fp32 规范版 + fp16 便捷版）、逐位置均值 + 前 64 主成分、PCA 基 top-448 均可直接用于后续实验（见 §7）。

## 6. 诚实边界（必须与数字同读）

1. **PCA 基与 retention 都在测试集上拟合**（含评测子集）⇒ 是 **oracle / transductive 上界**，不是可泛化的压缩率；真实训练/部署应在 train split 上拟合基。T3 的截断实验同样使用测试集拟合的基（因为是「数据侧上界」比较）。
2. **方差 ≠ PSNR ≠ 任务保真**：本报告的 retention 是像素重建前的 token 方差口径；T3 只测了像素 PSNR/L1/SSIM，未测 rFID 与 Phase 2 分类任务。
3. **单模型、单种子**：仅 240M/K=32/T=16 一个操作点；结论不能外推到 63M/K=64（其 E-A5 有效秩 0.736×K 量级相近但结构不同）或更大容量档。
4. **精度**：T2 用 fp16 token 分析（fp16 vs fp32 max\|Δ\|=0.0078，相对 2e-4；量化噪声方差 ~2e-8 vs 坐标方差 ~1，对 `rank≤99.9%`/方差比无影响）；T1 规范版与 T3 用 fp32；既有 PSNR 数字来自 GPU fp32，与本次 CPU fp32 解码可能有 ~1e-3 dB 级数值差异。
5. **有限样本**：N=5000、D=1248 时 `rank@τ` 有样本量依赖（split-half：两半 `rank@95` 差中位 1 / 最大 9，N 减半时 rank 绝对值系统性变小）；**只用同一 N 下的相对比较**，不把 335 当成模型的绝对内在维数。
6. **T3 子集**：200 张等间距（stride 25，100 类每类 2 张），CPU fp32 解码 0.79–0.86 s/img；与 5000 张全量数字只作相对比较（子集 base = 28.186 dB vs 全量 27.936 dB，子集偏高 0.25 dB）。
7. **z_s 的「位置」无空间语义**：是学习出的 special token 槽位，不是 patch 网格；逐位置 PCA 的 `rank` 对槽位编号无坐标含义。
8. **「7 个近常量位置」不等于可以无条件删**：它们可能是解码器的位置锚点/占位（decoder 有 `mem_pos`），删 token 需通过截断档评测验证（见 2026-10-19 K-sweep 的零训练截断档做法）。
9. 位置常量能量占比高（中位 0.672）部分来自编码器末层 LayerNorm 的下游效应（与 README §3 的 E-A5 注记同一提醒），不能单独当作「信息少」的证据。
